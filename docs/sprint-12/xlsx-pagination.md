# XLSX-пагинация: диагноз 15 расхождений числа страниц против LibreOffice

Числа: `oracle-out/report.md` (прогон 13.10.2026, LO 26.8.1.1, «Сравнено: 104,
пропущено: 0»), сводка — `docs/sprint-12/oracle.md` (коммит `3a20954`).
Расхождений 15, все «у нас меньше страниц». Разбор причин ниже построен на
трёх источниках:

1. diff `f16ea7b` («measure a sheet by painted cells and follow its print
   setup»): `visible_used_range` вместо `used_range`, чтение `pageSetup`
   листа, умолчание «уместить по ширине», объединения во всех полосах;
2. XML самих фикстур (`pageSetup`, ячейки, якоря рисунков/диаграмм);
3. **воспроизведение экспортёра до `f16ea7b`** (worktree на `f16ea7b^`,
   `mem_probe` по тем же 15 фикстурам) — точное «до» для каждого файла.

## Классы причин

| Класс | Наблюдается | Пояснение |
| --- | --- | --- |
| (а) высота строки с переносом не разворачивается | **нет** | Гипотеза для `values-long-text` опровергнута: в фикстуре нет `wrapText` (см. ниже). Фикстуры с `wrapText` (`text-cyrillic-wrap`) по страницам совпадают |
| (б) LO делит лист по столбцам, мы — нет | **нет** | Горизонтальное деление работает: до `f16ea7b` 11 из 15 совпадали с LO именно полосами столбцов. `layout-frozen-columns` внешне похож на (б), но причина иная (см. (д)) |
| (в) print setup / умолчание | **11 из 15, все новые** | Новое умолчание `resolve_page_scale` (уровень 5 из `f16ea7b`): «ничего не задано — уместить по ширине». LO и Excel при отсутствии настроек печатают **100 % и делят по столбцам**. Во всех 11 фикстурах `fitToWidth/fitToHeight` есть, но `pageSetUpPr fitToPage` нет — и LO, и мы их корректно игнорируем; расходится только умолчание |
| (г) сужение области из-за `visible_used_range` | **нет** | Во всех 15 фикстурах ячейки с содержимым (`<v>`), `visible_used_range` их не режет. Проверено по XML `content-sparse`/`edge-distant-cells`: дальние ячейки несут значения и видны |
| (д) LO расширяет печатную область, мы — нет | **4 из 15, все старые** | LO включает в печатную область переполнение текста за край последней колонки/строки и якоря рисунков/диаграмм; наша пагинация считает область только по ячейкам |

## Худшие 5 поимённо

1. **`values-long-text` 1/56** — класс (д), **было и до `f16ea7b`** (1/56).
   Строки 7800/10000 символов, `wrapText` нет, колонка дефолтная. LO разворачивает
   печатную область по горизонтальному переполнению неперенесённого текста;
   текст рисуется один раз и режется краем первой страницы, остальные 55 страниц
   пустые. Наш рендер первой страницы совпадает (SSIM 0,9919), расходится только
   число страниц. Гипотеза (а) не работает: высота строки тут ни при чём — строки
   не переносятся.
2. **`size-5x500x1` 1/50** — класс (в), **новое** (до `f16ea7b` было 50/50).
   Новое умолчание «уместить по ширине» сжимает 500 колонок в одну страницу;
   LO печатает 100 % и делит по 10 колонок на страницу.
3. **`size-50x50x1` 1/10** — класс (в), **новое** (до — 10/10). Тот же механизм.
4. **`content-sparse` 2/3** — класс (в), **новое** (до — 3/3). Fit-width сводит
   разлёт A1…CV500 к одной полосе столбцов; строки 1–500 режутся на 2 полосы.
5. **`content-dense` 2/6** — класс (в), **новое** (до — 6/6). LO: 2 кол. × 3 стр.
   при 100 %; fit-width сжимает оба измерения: у нас 1 кол. × 2 стр. Побочный
   SSIM 0,4376 — следствие сравнения только первых 2 страниц.

## Что было до `f16ea7b` и что стало новым

**До `f16ea7b` расходились ровно 4** (совпадает со «Спринт 11: не совпало у 4»;
воспроизведением `f16ea7b^` все они подтверждены):

- `values-long-text` 1/56 — (д) переполнение текста;
- `charts-five-kinds` 1/3 — (д) якоря диаграмм;
- `images-over-data` 1/2 — (д) дальний рисунок;
- `layout-frozen-columns` 1/2 — (д) переполнение «столбец 10» в K1.

**Новые после `f16ea7b` — 11** (все класс (в)): `size-5x500x1`, `size-50x50x1`,
`size-20x100x1`, `size-100x20x1`, `content-dense`, `content-sparse`,
`edge-many-columns`, `edge-first-row`, `edge-distant-cells`, `scale-1000-cells`,
`layout-column-widths`. У всех до `f16ea7b` число страниц совпадало с LO.
Причина одна: умолчание «уместить по ширине» (`resolve_page_scale`, уровень 5),
которого нет ни у LO, ни у Excel. Настройки листа в этих фикстурах
(`scale="100"`, `fitToWidth/fitToHeight="1"` без `fitToPage`) и LO, и мы трактуем
одинаково — расходится только то, что подставляем мы сами, когда «никто ничего
не задал».

Семантика `visible_used_range` (класс г) на этих 15 не сработала ни разу: все
ячейки с содержимым видны. На реальных книгах («Уведомления» 248 → 35) она
остаётся нужной — класс (в) чинится **не** её откатом.

## Рекомендуемые слайсы-фиксы (без самих фиксов)

### Ф1 — умолчание «уместить по ширине» (класс в, 11 фикстур)

- **Что:** убрать/пересмотреть уровень 5 `resolve_page_scale`
  (`crates/pdf/src/painter.rs`): при отсутствии настроек печатать 100 % и делить
  по столбцам, как LO/Excel. Уровни 1–4 (явные настройки вызывающего,
  `fitToPage` и `scale` листа) не трогать — это рабочая семантика `f16ea7b`.
- **Файлы:** `crates/pdf/src/painter.rs` (~10–20 строк), тесты
  `crates/pdf/tests/pagination.rs` (~40–80 строк), doc-комментарии
  `options.rs`/`lib.rs`.
- **Проверка:** воспроизведение `f16ea7b^` показало, что без умолчания все 11
  фикстур дают ровно числа LO; регрессий по остальным 89 книгам не ожидается
  (там до/после `f16ea7b` число страниц не менялось).
- **Риски:** широкие таблицы без настроек снова печатаются полосами столбцов —
  так печатает LO, но это ровно то, что `f16ea7b` называл дефектом; решение —
  продуктовый компромисс «эталон против удобства», зафиксировать в отчёте
  спринта. Не откатывать `visible_used_range`: реальные книги с пустым стилевым
  запасом снова раздуются.

### Ф2 — печатная область шире видимых ячеек (класс д, 4 фикстуры)

Общий механизм: LO печатает область «ячейки + переполнение содержимого +
якоря рисунков», наша пагинация — только ячейки. Вводится общий
`print_extent` в pdf-крейте (поверх `visible_used_range`, не вместо).

- **Ф2а — якоря диаграмм** (`charts-five-kinds`): расширить область
  прямоугольниками диаграмм листа; позиции уже парсятся (`crates/xlsx`
  `Sheet::charts`, раскладка в `painter::chart_layouts`).
  ~50–100 строк в `crates/pdf/src` + тесты. Риск низкий.
- **Ф2б — якоря рисунков** (`images-over-data`): то же для `Sheet::images`,
  включая дальние oneCellAnchor. ~30–60 строк + тесты. Риск низкий; отдельно
  проверить, что LO клампит дальний якорь на следующую страницу, а не тянет
  область до него целиком (иначе получим тысячи страниц вместо 2).
- **Ф2в — переполнение текста** (`values-long-text`, `layout-frozen-columns`):
  расширять область на ширину неперенесённого текста, вылезшего за край
  последней колонки/строки; требуется измерение текста (`crates/render`
  `text_measure`, метрики `skrifa` — уже есть в зависимостях). ~100–200 строк
  + тесты. Риск средний: точное повторение LO-кирка «пустая страница под
  переполнение одной колонки» хрупко; приемлемая граница — расширение области
  без погони за числом пустых страниц в каждом случае.

### Оценка суммарно

Ф1: ~50–100 строк, низкий риск, закрывает 11 из 15. Ф2: ~200–400 строк по трём
под-слайсам, закрывает 4 из 15. Классы (а), (б), (г) фиксов не требуют — по
корпусу они не наблюдаются; `visible_used_range` и уровни 3–4 `f16ea7b`
остаются как есть.

**Статус: Ф1 выполнен** (коммит `fe9ac21`): умолчание 100 % как у LO/Excel,
оракул по 11 фикстурам класса (в) — 11/11 совпадений по числу страниц.

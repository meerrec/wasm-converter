# Web Worker + OffscreenCanvas

## COOP/COEP

Для `SharedArrayBuffer` нужны заголовки:

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Путь без SAB не реализован: воркер безусловно зовёт `alloc_sab`, а `initOffscreen` ждёт `ready` именно с `sab` (см. [`adr/0004-sab-acceleration.md`](adr/0004-sab-acceleration.md), раздел «Где путь без SAB обрывается»). SAB-путь — единственный собранный.

На хостингах, которые не отдают свои заголовки (GitHub Pages), их ставит единственный service worker сайта — наш [`scripts/pages/sw.js`](../scripts/pages/sw.js), корневой и общий на весь сайт (вендоренного `coi-serviceworker.js` в демо больше нет). Корневая область нужна потому, что навигацию вложенного кадра обслуживает воркер, контролирующий родителя, а не тот, чья область совпадает с URL кадра: воркер в `/viewer/` не увидел бы навигацию `editor.html` в корне, и рамка редактора получила бы `ERR_BLOCKED_BY_RESPONSE` — изолированная страница не впускает вложенный документ без COEP. Заголовки он ставит всем ответам (COEP нужен и воркер-скриптам движка — без него в их собственном ответе Chromium режет `spell.js` и `x2t.worker.js`, и конвертер не поднимается), кэшей не держит, а включается на первом заходе, поэтому страница перезагружается. Изоляцию получают только браузеры, умеющие встраивать кадр в изолированную страницу — сегодня это Chromium; проверка стоит и на страницах, и в самом воркере (движок регистрирует его мимо них). Firefox и Safari остаются без изоляции: вьюер едет на транспорте `bytes` (ADR-0021), а кадр редактора у неизолированного родителя грузится.

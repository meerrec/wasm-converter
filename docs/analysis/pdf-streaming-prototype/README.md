# Прототип стриминга PDF — справочный код

Это **не часть сборки**: файлы лежат вне `crates/`, workspace их не видит и не компилирует.
Сохранены потому, что на них опирается задача B2a (сессия стриминга в `vendor/printpdf`), а
исходный каталог прототипа жил во временном `/tmp` и мог быть потерян.

## Что это

- `streaming.rs` — модуль-прототип для printpdf 0.8.2: собственный сериализатор объектов,
  `StreamSession::{begin, write_page, finish}`, инкрементальная xref, `CountingWriter`.
  Написан как `printpdf/src/streaming.rs` и в прототипе подключался к копии крейта.
- `spike.rs` — измерительная обвязка: генерирует синтетическую книгу, пишет её тремя путями
  (baseline / stream готового документа / lazy-запись по страницам), меряет RSS и валидирует
  результат через lopdf (число страниц, побайтовое сравнение контента, outline, аннотации).

## Что прототип показал

| Путь | 50 страниц | 500 страниц | Рост |
| --- | ---: | ---: | ---: |
| baseline (текущий printpdf) | 55,8 МиБ | 503,3 МиБ | ×9,0 |
| lazy-запись (sink) | 7,0 МиБ | **7,4 МиБ** | ×1,06 |

Плюс: PDF валиден, контент всех 500 страниц совпал с baseline побайтово, закладки и `/Annots`
пережили постраничную запись.

## Чего прототип НЕ проверял

- Механику пре-прохода под subset-шрифты (прототип писался на стандартных шрифтах) — главный
  открытый вопрос B2.
- Сжатие: точка пересечения с правками `serialize.rs:289-290, 392-394` указана, но в прототипе
  оно выключено.
- `qpdf --check`: локально утилиты нет, валидация — разбором lopdf; внешняя проверка остаётся CI.

Полный разбор — `docs/analysis/pdf-streaming-spike.md`, решение — `docs/adr/0010-printpdf-fork.md`.

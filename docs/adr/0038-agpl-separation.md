# ADR-0038: Вынос AGPL-части в отдельный репозиторий `meerrec/eurooffice-demo`

**Статус:** Принято
**Дата:** 21.10.2026
**Контекст:** Эпик 2 архитектурного аудита (`docs/architecture.md`, критическое замечание №5)
**Связанные ADR:** [ADR-0024](0024-x2t-rendering-backend.md) (x2t как рисующий
бэкенд — no-go, но конвертер остаётся обвязкой), [ADR-0023](0023-libreoffice-wasm-exact-backend.md)
(LOWA — no-go), [ADR-0039](0039-cancel-v1-non-goals.md) (отмена non-goal'ов v1)

---

## Контекст

- Монорепозиторий целиком лицензирован Apache-2.0, но в нём живёт код, который
  грузит или собирает AGPL-3.0-only движок Euro-Office (форк ONLYOFFICE):
  `packages/eurooffice` (клиент Embed API), `packages/x2t` (обвязка wasm-конвертера
  ONLYOFFICE, `vendor/` — ~46 МБ артефактов под Git LFS), `packages/browser-convert`
  (конвертерная обвязка поверх x2t), `scripts/eurooffice/assemble.mjs` (сборка сайта
  движка в `build/eurooffice/site`), демо-страницы `examples/viewer/src/pages/{convert,eurooffice}`
  и их e2e, а также стейджинг Pages (`scripts/pages/stage.mjs` — двухуровневый:
  корень сайта — движок, `/viewer/` — демо).
- Граница лицензий размыта: в репозитории рядом лежат Apache-код и код,
  существующий только ради AGPL-движка; проверка «в монорепозитории нет файлов
  AGPL» grep'ом не формализована, а сборка Pages тянет LFS-артефакты движка в
  каждый прогон демо.
- Аудитория у этих частей своя: конвертер/редактор — демо движка, а не
  просмотрщик OOXML; их релизный цикл и лицензионная ответственность с ядром не
  связаны.

## Решение

1. **Граница:** всё, что грузит или собирает AGPL-движок Euro-Office/x2t,
   живёт в отдельном репозитории `meerrec/eurooffice-demo`. Монорепозиторий
   ссылается на него только README-ссылкой, кодом — никогда.
2. **Перенос свежей историей:** `git subtree`/`filter-repo` не используется —
   дешевле и лицензионно чище скопировать файлы как есть и сделать в новом
   репозитории один корневой коммит. Старая история остаётся в монорепозитории.
3. **Состав нового репозитория:** `packages/{eurooffice,x2t,browser-convert}`
   (x2t `vendor/` — заново через `git lfs track`), `scripts/eurooffice/`,
   `scripts/{stage.mjs,index.html,sw.js,check-route.mjs}` (из `scripts/pages/`),
   страницы демо `pages/{convert,eurooffice}` и e2e `e2e/{convert,eurooffice}`,
   `experiments/x2t-spike/`, собственный `pnpm-workspace`, `pages.yml` с
   `lfs: true` и деплой на собственный Pages-сайт.
4. **Монорепозиторий после переезда:** перечисленные пакеты/страницы/скрипты
   удаляются; `pages.yml` собирает только viewer-демо (без `lfs: true`, без
   `assemble.mjs`, без сборки трёх пакетов); демо остаётся одностраничным
   viewer'ом (`#/docx`, `#/xlsx`), маршруты `#/convert` и `#/eurooffice` уходят
   вместе с движком.
5. **Проверка чистоты — grep-гейт:** после переезда
   `grep -riE 'eurooffice|x2t|browser-convert'` (без `node_modules/dist/target/.git`)
   в монорепозитории находит только документирующие ссылки (README, ADR,
   исторические спринт-отчёты), не код.
6. **Взамен sw-патча Pages в монорепозитории** остаётся корневой
   `scripts/pages/sw.js`, но упрощённый до viewer-only: он ставит COOP/COEP
   демо, движок ему больше не нужен (ветка `credentialless` для кадра редактора
   удаляется).

## Альтернативы

- **Оставить AGPL-часть в монорепозитории** — отвергнуто: аудит прямо помечает
  лицензионную нечистоту критическим замечанием; разделение — единственный
  способ сделать монорепозиторий доказуемо Apache-2.0.
- **`git filter-repo` с полной историей** — отвергнуто: дорого, а старая история
  в монорепозитории всё равно сохраняется (полный scrub истории — отдельное
  решение); свежее копирование не теряет ничего ценного для нового репозитория.
- **Пакеты в отдельном монорепозитории, но демо-страницы — в основном** —
  отвергнуто: страницы конвертера/редактора существуют только ради движка, их
  место — рядом с ним, иначе в основном репозитории остаётся код, импортирующий
  AGPL-пакеты.
- **Vendor-артефакты без Git LFS** — отвергнуто: 46 МБ бинарников в истории
  раздувают клоны; LFS-паттерн перенесён из монорепозитория как есть.

## Последствия

- Монорепозиторий доказуемо Apache-2.0: grep-гейт из п. 5 проверяется вручную и
  описывается в `AGENTS.md`.
- GitHub Pages монорепозитория публикует только демо просмотрщика; сайт движка
  с конвертером и редактором деплоится из `meerrec/eurooffice-demo`.
- Ссылки на страницы «Конвертер» и «Euro-Office» в README заменяются ссылкой на
  новый репозиторий; `packages/{x2t,eurooffice,browser-convert}` больше не
  публикуются релизным контуром монорепозитория.
- Демо-оболочка (Vite-приложение) для перенесённых страниц в новом репозитории
  собирается заново — страницы перенесены как источник, их импорты
  (`../../lib/viewer_urls.js` и т. п.) переподключаются там.
- Удаление из монорепозитория снимает LFS-зависимость со сборки Pages демо:
  `actions/checkout` больше не качает `lfs: true`.

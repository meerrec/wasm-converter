# ADR-0037: OpenTelemetry-инструментация — opt-in и только API

**Статус:** Принято
**Дата:** 21.10.2026
**Контекст:** Спринт 15, слайс «индустриализация: наблюдаемость»
**Связанные ADR:** [ADR-0027](0027-npmjs-primary-registry.md) (реестры npm),
[ADR-0028](0028-typed-wire-protocol.md) (wire-типы протокола),
[ADR-0031](0031-streaming-zip.md) (стримовый вход и прогресс)

---

## Контекст

- Матрица To-Be `docs/architecture.md` заменяет «локальные callbacks» на
  «OpenTelemetry | APM»: потребителю вьюера нужен стандартный способ снимать
  метрики открытия и экспорта, а не собственный набор колбэков на каждый
  вызов.
- Политика `docs/agent-contract.md` §7 — «файлы пользователя не покидают
  устройство» — запрещает сетевые вызовы в рантайме. Экспортёр OpenTelemetry
  по умолчанию отправляет спаны по сети, поэтому инструментация обязана быть
  opt-in: без явной регистрации провайдера потребителем ничего не уходит.
- `@meerrec/core` — библиотека, а не приложение: SDK, батч-процессоры и
  экспортёры (OTLP, Jaeger, консоль) — ответственность потребителя. Тащить их
  в зависимости пакета значит навязывать транспорт и раздувать бандл.
- Бюджет `@meerrec/core` из `ROADMAP.md` §9 — 200 КБ gzip (`index.js`).
  Полный SDK OpenTelemetry в него не влезает; API-пакет — влезает.

## Решение

1. **Только `@opentelemetry/api`.** Это обычная зависимость пакета с
   диапазоном `^1.0.0`. SDK, процессоры и экспортёры в `dependencies` не
   входят. `@opentelemetry/sdk-trace-base` — только `devDependency` для
   тестов; в опубликованный пакет он не попадает.
2. **Экспортёра по умолчанию нет.** `telemetry.ts` создаёт tracer
   `trace.getTracer('@meerrec/core', VERSION)`, где `VERSION` — поле `version`
   из `package.json`. Пока потребитель не зарегистрировал провайдера, API
   отдаёт no-op-трейсер: `span.isRecording() === false`, атрибуты не
   записываются, `span.end()` ничего не отправляет. Сетевых вызовов в
   рантайме нет — политика §7 сохранена.
3. **Имена спанов — операции, а не кадры.** `viewer.open` — один спан на
   вызов `open`; `viewer.export` — один спан на вызов `exportPdf`/`exportPng`.
   Кадровый цикл спанов не создаёт: статистика `tick` остаётся локальной
   (подписка `onTick`), иначе на 60 FPS инструментация стоила бы дороже
   работы.
4. **Атрибуты — только размеры, формат и идентификаторы.** Закрытый набор:
   `format` (`'xlsx' | 'docx'`), `kind` (`'pdf' | 'png'`), `bytes` (длина
   входа при открытии или результата при экспорте), `sheetCount`/`pageCount`.
   Байты документа, их фрагменты, имена файлов, пути и текст в атрибуты не
   попадают никогда: спаны уходят во внешний APM, и содержимое документа —
   не телеметрия.
5. **Спан всегда завершается.** `startSpan` создаёт спан, `endSpan` в
   `try/finally` вызывает `span.end()`. При ошибке и только при
   `span.isRecording()` — `recordException` и статус `ERROR`; сама ошибка
   пробрасывается дальше без подмены типа и сообщения. Без провайдера
   `endSpan` — no-op кроме `end()`.
6. **Граница модуля.** `telemetry.ts` — внутренний модуль `@meerrec/core`,
   в публичный `index.ts` не экспортируется. Включение — регистрация
   провайдера потребителем (`provider.register()`); выключение — её
   отсутствие. Отдельной опции `telemetry: false` нет: молчаливая
   инструментация не должна требовать конфигурации.

## Альтернативы

- **Полный SDK и экспортёр в `@meerrec/core`** — отвергнуто: тянет транспорт,
  сетевые вызовы по умолчанию (нарушение §7) и не влезает в бюджет 200 КБ.
- **Свои callbacks вместо OpenTelemetry** — отвергнуто: матрица To-Be требует
  стандарт, а собственный набор колбэков уже есть (`onTick`, `onProgress`) и
  остаётся для локальной диагностики.
- **Спан на каждый кадр** — отвергнуто: накладные расходы в горячем цикле,
  шум в APM и никакой диагностической ценности поверх `PaintStats`.
- **Декораторы/прокси над handle вместо явных точек** — отвергнуто:
  неявная подмена методов ломает идентичность функций и хуже читается;
  шесть явных `try/finally` дешевле и видны при ревью.
- **Экспортёр по умолчанию с отключением флагом** — отвергнуто: «opt-out»
  означает, что данные уже утекли до первого вызова; политика требует
  обратного.

## Последствия

- Потребитель, зарегистрировавший провайдер, получает спаны `viewer.open` и
  `viewer.export` с атрибутами размеров; без регистрации поведение и
  производительность не меняются.
- `@opentelemetry/api` добавляется в `dependencies` `@meerrec/core`;
  `@opentelemetry/sdk-trace-base` — только в `devDependencies` для
  `test/telemetry.spec.ts`.
- Бюджет core (200 КБ gzip) проверяется `pnpm size-limit`: с
  `@opentelemetry/api` в зависимостях `index.js` — 13.4 КБ gzip (Спринт 15,
  запас до бюджета ~93 %). Если API-пакет выведет строку за бюджет,
  предрешённый откат — динамический `import('@opentelemetry/api')` с кэшем;
  бюджет при этом не ослабляется.
- Атрибуты фиксированы кодом: расширение набора (например, `renderMode`)
  допустимо, но содержимое документа — нет.

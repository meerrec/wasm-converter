# ADR-0032: Отмена операций — кооперативный флаг и `AbortSignal`

**Статус:** Принято
**Дата:** 21.10.2026
**Контекст:** `docs/architecture.md`, критическое замечание №4 — тяжёлая
раскладка блокирует воркер без возможности отмены
**Связанные ADR:** [ADR-0030](0030-format-plugin-traits.md) (вариант
`EngineError::Cancelled` заведён в trait-слое), [ADR-0031](0031-streaming-zip.md)
(отмена загрузки потока — бесплатно, до `end-stream`)

---

## Контекст

- Раскладка DOCX (150 страниц) и сборка кадра плотного XLSX идут в воркере
  синхронно: wasm однопоточный, принудительного прерывания нет. `destroy()`
  на TS-стороне лишь отклоняет ожидающие промисы — уже начатая раскладка
  добегает до конца, блокируя воркер.
- Отмена загрузки стрима (ADR-0031) уже бесплатна: чанки просто не доезжают.
  Здесь — отмена начатого разбора/раскладки/сборки кадра.

## Решение

1. **Кооперативная модель.** Принудительного прерывания в wasm нет, поэтому
   флаг отмены проверяется в точках между единицами работы:
   - DOCX — между блоками тела при раскладке (граница мельче страницы, дешевле
     страничной: проверка — чтение `Cell<bool>`, а документ из десятков тысяч
     блоков отменяется на первом же блоке после флага);
   - XLSX — между полосами видимых строк при сборке кадра.
2. **Флаг — `&Cell<bool>`, передаётся явно.** `thread_local!` в библиотечных
   крейтах (`xlsx`, `docx`) не вводится: тесты должны уметь дёргать флаг без
   глобального состояния. Экспорты wasm держат `thread_local!`-флаг
   (`set_cancel(bool)`, одно активное тяжёлое вычисление на воркер) и сбрасывают
   его в начале каждой операции.
3. **Ошибки.** `docx::LayoutError` и `xlsx::XlsxError` получают вариант
   `Cancelled` (публичные типы: у `docx::Error` он уже `#[non_exhaustive]`;
   `LayoutError` расширяется так же). Публичные точки входа не ломаются:
   `layout_document` остаётся обёрткой над новым
   `layout_document_with_cancel(…, cancelled: &Cell<bool>)` с флагом «не
   отменено», а `xlsx::paint::build` получает параметр `cancelled` — вызовов
   у него немного, и все они внутри репо.
4. **Протокол.** InMsg `cancel { id }`; `WorkerErrorCode` получает
   `'cancelled'`. Воркер по `cancel` ставит флаг; `Cancelled` из wasm
   превращается в `WorkerErrorMsg { id, code: 'cancelled' }` и не роняет
   кадровый цикл. Ошибка отмены адресная: остальные запросы продолжают
   работать.
5. **Публичный API.** `open(source, { signal? })`,
   `exportPdf({ signal? })`, `exportPng({ signal? })` (у DOCX ещё
   `exportDocxPdf`/`exportText`): одноразовый listener на `abort` шлёт `cancel`
   в воркер и снимается в `finally`. `destroy()` шлёт `cancel` всем ожидающим
   и реджектит их с кодом `'cancelled'`. Новый `open` при активном предыдущем
   сначала отменяет старый.
6. **Отмена не портит состояние.** После `Cancelled` воркер цел: следующая
   операция работает как обычно (wasm-тест: отменённый `open` 150-страничной
   фикстуры → ошибка `cancelled` → обычный `open` проходит).

## Последствия

- `xlsx::paint::build` меняет сигнатуру (добавляется `cancelled`) — правятся
  вызовы в wasm-крейтах и тестах; поведение без отмены не меняется.
- Отмена раскладки DOCX останавливает текущий `layout_pass`; уже собранные
  страницы не используются — операция завершается ошибкой.
- `renderMode: 'main'` отмену не меняет: парс и раскладка и там живут в
  воркере.

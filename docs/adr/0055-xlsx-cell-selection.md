# ADR-0055: Выделение ячеек XLSX — полный лист и Excel-взаимодействие

**Статус:** Принято
**Дата:** 18.11.2026
**Контекст:** требование реализовать выделение ячеек с поведением Excel на всём
листе до `XFD1048576`, без операций изменения содержимого
**Связанные ADR:** [ADR-0003](0003-render-boundary.md) (граница `render`),
[ADR-0021](0021-frame-transports.md) (транспорты кадра),
[ADR-0025](0025-xlsx-layout-boundary.md) (раскладка XLSX),
[ADR-0028](0028-typed-wire-protocol.md) (wire-типы),
[ADR-0029](0029-main-thread-render-backend.md) (main-fallback),
[ADR-0043](0043-runtime-text-edits.md) (рантайм-правки),
[ADR-0044](0044-unified-execution-path.md) (единый путь кадра),
[ADR-0054](0054-ooxml-editor.md) (редактор примера)

---

## Контекст

- `createXlsxViewer` умеет только асинхронно определить `[row, col]` под точкой
  и изменить текст одиночной ячейки. Постоянной активной ячейки, диапазонов,
  клавиатурной навигации и визуального выделения нет.
- Демо использует последнюю ячейку под курсором как цель команд. Это не
  эквивалент активной ячейке: после ухода указателя с листа или при расширении
  диапазона цель становится неоднозначной.
- Текущий `paint::hit_test` не различает ячейку, заголовок строки, заголовок
  столбца и общий угол. Он также всегда создаёт геометрию с включёнными
  заголовками, хотя интерфейс умеет их скрывать.
- `SheetLayout::new` отводит под лист используемый диапазон и одну строку и
  столбец запаса. Это подходит печати, но не позволяет перейти к произвольной
  ячейке `A1:XFD1048576`, выделить полный столбец или показать весь лист.
- Простое увеличение `spacer` до полного размера листа не работает при всех
  поддерживаемых зумах: CSS-размер полного листа превышает ограничения
  браузеров. Логическая координата прокрутки должна быть отделена от DOM.
- Выделение строки, столбца или всего листа нельзя представлять списком ячеек.
  Даже ограничение редактора примера в 100 000 ячеек неприменимо к этому
  состоянию.

## Цель и границы

Эталон поведения — Microsoft 365 Excel для Windows. На macOS системные
модификаторы адаптируются по отдельной таблице: добавление несмежного
выделения выполняется через Command, а не через конфликтующий с контекстным
меню Ctrl+click.

В объём входят активная ячейка, одиночные и несмежные диапазоны, выделение
строк, столбцов и всего листа, клавиатурная навигация, автопрокрутка и
программный API. Все адреса Excel доступны: 16 384 столбца и 1 048 576 строк.

В объём не входят:

- автозаполнение и перетаскивание маркера заполнения;
- перемещение или изменение содержимого диапазона;
- копирование, вырезание, вставка и буфер обмена;
- ввод значений и формул, контекстное меню;
- расширение редакторских команд на несмежные диапазоны;
- чтение и запись `sheetView/selection` в OOXML;
- выделение в XLSB и ODS. Общие типы не должны препятствовать последующему
  переиспользованию, но их взаимодействие — отдельная задача.

Маркер заполнения рисуется как часть визуального состояния, но не имеет
обработчика операции. Выделение — рантайм-состояние интерфейса: оно не меняет
`Workbook::edits`, байты документа, PDF или экспортируемое содержимое.

## Решение

### 1. Разреженная модель выделения

Внутреннее состояние контроллера на main:

```ts
interface CellAddress {
  row: number;
  col: number;
}

interface CellRange {
  start: CellAddress;
  end: CellAddress;
}

interface SelectionState {
  sheetIndex: number;
  active: CellAddress;
  anchor: CellAddress;
  cursor: CellAddress;
  ranges: CellRange[];
  mode: 'normal' | 'extend' | 'add';
}
```

`active` определяет Name Box и цель существующей одиночной правки, `anchor` —
неподвижный конец текущего диапазона, `cursor` — противоположный конец.
`ranges` содержит нормализованные прямоугольники в порядке добавления. Адреса
0-based внутри движка, ограничены `MAX_ROW`/`MAX_COL`; диапазоны не
разворачиваются в ячейки и не объединяются автоматически, поскольку порядок и
пересечения важны для несмежного выделения.

Состояние хранится отдельно для каждого листа. Переключение листа восстанавливает
его выделение, открытие другой книги очищает все состояния и выбирает `A1` на
первом показанном листе. `Escape` отменяет текущий drag или режим
extend/add, но не очищает уже принятое выделение.

### 2. Контроллер событий на main, модельные решения в Rust

`@meerrec/core` владеет Pointer Events, клавиатурой, фокусом, модификаторами,
текущим состоянием и автопрокруткой. React не участвует в горячем пути и не
получает обновление на каждый `pointermove`.

Rust в `crates/xlsx` остаётся единственным источником раскладки и сведений о
книге. Через wasm/worker предоставляются чистые операции:

- расширенный hit-test;
- объединение, накрывающее ячейку, и нормализация диапазона по объединениям;
- следующая видимая строка или столбец;
- цель Ctrl+стрелки по границам данных и пустых участков;
- используемый диапазон для Ctrl+End и Ctrl+A;
- логические границы ячейки или диапазона для прокрутки.

Для этих операций не создаётся вторая модель книги на main и не выгружаются
списки всех объединений, скрытых строк или ячеек.

`pointermove` коалесцируется по `requestAnimationFrame`; одновременно ожидается
не больше одного hit-test, а после его ответа отправляется только последняя
точка. У каждого взаимодействия есть монотонный номер: поздний ответ не может
изменить более новое выделение. Drag использует `setPointerCapture` и
завершается на `pointerup`, `pointercancel`, потере фокуса и `destroy`.

Клавиатура обслуживается только на сфокусированной области вьюера. События из
`input`, `textarea`, `contentEditable` и ленты не перехватываются.
`preventDefault` вызывается только для обработанного сочетания.

### 3. Совместимый протокол и публичный API

Существующий `hitTest(): Promise<[number, number] | null>` сохраняется. Новый
запрос возвращает дискриминированный результат:

```ts
type SheetHit =
  | { kind: 'cell'; row: number; col: number }
  | { kind: 'row-header'; row: number }
  | { kind: 'column-header'; col: number }
  | { kind: 'select-all' }
  | { kind: 'outside' };
```

Он получает фактический `showHeaders`, зум, DPR, логическую прокрутку и
закрепления. Старый `hit-test` не меняет форму ответа; гиперссылки продолжают
использовать общую геометрию ячеек.

В `crates/core/src/wire.rs` добавляются адрес, диапазон и снимок выделения для
кадра и навигационных ответов; TypeScript-типы генерируются через
`pnpm gen:wire`. Конверты `InMsg`/`OutMsg` остаются в
`packages/core/src/protocol.ts`. Выделение передаётся только в интерактивный
запрос кадра, а не в PDF.

Публичный API `XlsxViewerHandle`:

```ts
getSelection(): XlsxSelection | null;
setSelection(
  reference: string | CellRange,
  options?: { add?: boolean; scrollIntoView?: boolean },
): Promise<void>;
clearSelection(): void;
scrollCellIntoView(address: CellAddress): Promise<void>;
onSelectionChange(handler: (selection: XlsxSelection) => void): () => void;
```

Публичный снимок содержит лист, активную ячейку и нормализованные диапазоны.
`setSelection` принимает адрес или диапазон A1, включая полные строки и
столбцы; `scrollIntoView` по умолчанию включено. Методы завершаются после
нормализации в Rust и применения состояния на main. Подписка не вызывается для
устаревших или отклонённых запросов.

### 4. Поведение выделения

Обязательная матрица:

| Ввод | Результат |
|---|---|
| click по ячейке | Новое одиночное выделение, активная ячейка под точкой |
| drag по ячейкам | Диапазон от якоря до курсора в любом направлении |
| Shift+click, Shift+стрелки | Расширение от неизменного якоря |
| Ctrl+click/drag | Добавление ячейки или диапазона; на macOS — Command |
| click/drag по заголовкам | Полные строки или столбцы, включая Shift и Ctrl |
| Общий левый верхний угол | Весь `A1:XFD1048576` |
| Стрелки | Перемещение активной ячейки с пропуском скрытых |
| Ctrl+стрелки | Переход по границам данных и пустых областей |
| Home, Ctrl+Home, Ctrl+End | Столбец A, `A1`, последняя используемая ячейка |
| PageUp/PageDown | Видимая страница по вертикали |
| Alt+PageUp/PageDown | Видимая страница по горизонтали |
| Shift+Space / Ctrl+Space | Текущая строка / текущий столбец |
| Ctrl+A | Область данных активной ячейки; повторно — весь лист |
| Tab/Shift+Tab | Следующая/предыдущая ячейка внутри диапазона с wrap |
| Enter/Shift+Enter | Следующая/предыдущая строка внутри диапазона с wrap |
| F8 / Shift+F8 | Режим расширения / добавления выделения |
| Ctrl+Backspace | Показать активную ячейку без изменения диапазона |
| Escape | Отменить drag или специальный режим |

Shift-применимо и к постраничной навигации, Home и Ctrl+End. При клике по
объединённой ячейке активной становится её левая верхняя ячейка, а диапазон
охватывает всё объединение. Расширение через объединения включает их целиком.
Скрытые строки и столбцы не получают фокус и имеют нулевой размер.

При drag у края окна включается автопрокрутка; скорость растёт с удалением
указателя за границу. Кадр и hit-test используют одно логическое смещение.
Прокрутка колесом, зум и смена размеров окна сами по себе выделение не меняют.

Существующий `onHyperlink` сохраняет текущее поведение: клик одновременно
устанавливает выделение и запрашивает ссылку. Изменение правил перехода по
ссылкам в эту задачу не входит.

### 5. Отрисовка в DisplayList

Подсветка добавляется в `crates/xlsx` при сборке кадра. Отдельного DOM/SVG или
Canvas-overlay нет: worker/main и SAB/bytes получают одну картинку через
существующий путь ADR-0044.

Порядок слоёв: содержимое листа, полупрозрачная заливка диапазонов, рамки,
подсветка заголовков, активная ячейка и маркер заполнения. Заливка не закрывает
текст; активная ячейка не получает общую заливку. Диапазон имеет внешнюю
акцентную рамку, выбранные строки и столбцы — отличающийся фон заголовков.

Для каждого диапазона вычисляются только пересечения с видимыми квадрантами.
Никаких циклов по всем выделенным ячейкам нет. Закреплённые области обрезаются
по тем же `Region`, что содержимое; рамка не дублируется на стыке квадрантов и
не рисуется за пределами окна. Выключение сетки или заголовков не меняет
модель выделения.

По возможности используются существующие команды заливки, линий и клипов.
Новый тег `DrawCommand` допускается только при недостаточности текущих команд и
требует синхронного поднятия `DL_VERSION` и обновления потребителей.

### 6. Полный лист и виртуальная прокрутка

Для интерактивного пути добавляется полная раскладка
`16 384 × 1 048 576` с размерами строк и столбцов из модели. Существующая
укороченная раскладка остаётся у PDF и других потребителей, которым нужен
только используемый диапазон. Общие функции границ и обратного поиска не
дублируются.

На main появляется `LogicalScroll`: независимые от DOM логические смещения в
пикселях раскладки. `viewport.x/y`, hit-test и `scrollCellIntoView` используют
только его. Canvas по-прежнему сдвигается на фактический DOM scroll.

При превышении безопасного CSS-размера распорка ограничивается, а чистый модуль
отображения координат связывает DOM scroll с полным логическим диапазоном.
Требования к отображению:

- любая ячейка достижима при зуме 10–400%;
- около текущей позиции колесо и перетаскивание ползунка сохраняют
  предсказуемое локальное масштабирование, без глобального ускорения колеса во
  столько раз, во сколько уменьшена распорка;
- `toLogical(toDom(x))` возвращает исходную позицию с пиксельной точностью;
- `scrollTo`, смена зума, resize и автопрокрутка используют один модуль;
- при смене зума видимая активная ячейка сохраняется;
- отсутствуют NaN, отрицательные смещения и выход за границы листа.

Для малых документов отображение остаётся тождественным. Реализация не должна
менять `RenderAdapter`, `TransportAdapter` или формат SAB-кольца.

### 7. Демо и доступность

Name Box показывает адрес активной ячейки или текущего диапазона и позволяет
ввести адрес для перехода. Существующая одиночная правка и одиночные команды
используют `active`, а не последний hover. Их редакторское поведение не
расширяется. После повторного открытия байтов редактором восстанавливаются
текущие лист и совместимое с новой моделью выделение; если адрес исчез,
выбирается ближайшая допустимая ячейка.

Область вьюера получает видимый фокус, `role="grid"` и
`aria-multiselectable="true"`. Активный адрес и размер выделения доступны через
имя сетки и отдельный live-region; объявления во время drag коалесцируются.
`aria-activedescendant` и `aria-selected` не используются без реальных DOM-узлов
ячеек. Полноценная виртуализированная DOM-семантика всех ячеек в задачу не
входит.

## Этапы внедрения

1. Типы, расширенный hit-test, модельные навигационные запросы и их нативные
   тесты.
2. Контроллер, активная ячейка, click/drag/Shift/Ctrl и базовая отрисовка.
3. Заголовки, несмежные диапазоны, клавиатура и автопрокрутка.
4. Полная раскладка, `LogicalScroll`, Name Box и программные переходы.
5. Объединения, скрытые ячейки, закрепления, отдельные состояния листов и
   доступность.
6. Сквозная проверка всех режимов кадра, браузеров, зумов и бюджетов.

Полная прокрутка — самостоятельный блокирующий этап поставки: промежуточная
версия на используемом диапазоне не считается выполнением этого ADR.

## Проверка

- Нативные Rust unit/proptest: границы `XFD1048576`, нормализация обратных
  диапазонов, Ctrl-навигация, скрытые ячейки, объединения и полные строки,
  столбцы и лист.
- Vitest: автомат состояния, модификаторы, stale-ответы, один незавершённый
  hit-test, pointer capture, отмена drag, destroy и отображение прокрутки.
- Playwright в Chromium, Firefox и WebKit: мышь и клавиатура, обратный drag,
  несмежные диапазоны, заголовки, Ctrl+A дважды, Tab/Enter, автопрокрутка,
  переход к `XFD1048576` и возврат к `A1`.
- Отдельные прогоны DPR 2, worker/main и доступные транспорты; зум 10%, 100%,
  400%; скрытая сетка и заголовки; закреплённые строки и столбцы.
- Сложность отрисовки зависит от числа диапазонов и видимой области, но не от
  числа выделенных ячеек. Не более одного кадра на rAF и без React-render на
  каждый pointermove.
- Обязательные гейты: `pnpm build:wasm`, нулевой diff после `pnpm gen:wire`,
  `cargo test --workspace --all-features`, clippy,
  `pnpm turbo run typecheck test build` и `pnpm size-limit`.

## Рассмотренные варианты

- **DOM/SVG-overlay поверх canvas** — отклонено: дублирует геометрию,
  закрепления, DPR и обрезку; требует отдельной синхронизации с прокруткой.
- **Второй canvas для подсветки** — отклонено: уменьшает число команд в основном
  кадре, но создаёт второй путь отрисовки и те же проблемы координат.
- **Состояние целиком в React** — отклонено: лишние render на горячем вводе и
  дублирование состояния вне императивного вьюера.
- **Состояние целиком в Rust/worker** — отклонено: усложняет фокус, публичные
  подписки и синхронную обработку клавиш; main всё равно владеет событием.
- **Список выделенных ячеек** — отклонено: не представляет полный лист и
  масштабируется от площади выделения.
- **Увеличить существующий spacer до полного листа** — отклонено: упирается в
  предельные CSS-размеры браузеров при полном листе и большом зуме.
- **Ограничиться используемым диапазоном** — отклонено подтверждённым
  требованием полного `XFD1048576`.
- **Изменить старый `hit-test`** — отклонено ради совместимости публичного API;
  добавляется отдельный расширенный запрос.

## Последствия

- `@meerrec/core` получает новый публичный API и клавиатурный фокус; это
  осознанное расширение поведения вьюера.
- В протоколе появляются новые запросы и выделение в опциях интерактивного
  кадра; DisplayList меняется только если существующих команд недостаточно.
- Полная раскладка увеличивает не память модели, а логический диапазон
  координат: ячейки и диапазоны остаются разреженными.
- Виртуальная прокрутка затрагивает `viewport`, `scrollTo`, зум, hit-test и
  автопрокрутку одновременно; частичный перенос недопустим из-за рассинхронизации
  курсора и кадра.
- Размер wasm и JS должен остаться в существующих бюджетах либо бюджет
  пересматривается отдельным обоснованным изменением, а не молча.
- Автозаполнение, перемещение диапазона, clipboard и запись выделения в файл
  потребуют отдельных решений поверх этого API.

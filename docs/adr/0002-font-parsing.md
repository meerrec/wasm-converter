# ADR 0002: Чем парсить шрифты — решаем в Фазе 4

**Статус:** принято (Фаза 3)
**Контекст:** `crates/pdf/Cargo.toml`, `crates/render/src/font.rs`

## Задача

Метрики глифов нужны, чтобы считать ширину текста: без них не работают ни
перенос строк, ни раскладка колонок, ни PDF-экспорт. ROADMAP §4 называет для
этого `ttf-parser` 0.24 вместе с `rustybuzz` для shaping.

## Что изменилось

`ttf-parser` помечен `unmaintained` — RUSTSEC-2026-0192: автор заявил, что
исправлений не будет, и рекомендовал `skrifa` из проекта Google Fonts
(«fontations»). Обновления, которое закрывает вопрос, нет.

При этом в коде парсер шрифтов **не использовался**: зависимость была объявлена
в `doc-converter-pdf`, но встречалась только в доккомментарии. То есть аудит
`cargo deny` падал из-за крейта, который ничего не делал.

## Решение

Зависимость снята, пока она не нужна. Никаких `ignore` в `deny.toml` не
добавлено: незачем оставлять в конфиге исключение для крейта, которого в графе
зависимостей нет.

Выбор между `ttf-parser` (с исключением в аудите) и `skrifa` — решение Фазы 4,
когда метрики понадобятся по-настоящему. К этому моменту будет видно, что
происходит с `rustybuzz`: если он к тому времени сам перешёл на `skrifa` или на
собственный парсер, вопрос решится сам.

## Следствия

- `cargo deny check` чист без исключений — исключение, добавленное «на всякий
  случай», обычно переживает причину, по которой его добавили.
- В `[workspace.dependencies]` запись `ttf-parser` осталась: она не попадает в
  граф зависимостей, пока ни один крейт её не требует, и служит напоминанием о
  плане.
- Фаза 4 обязана принять решение осознанно: молча вернуть `ttf-parser` уже
  нельзя — аудит снова упадёт.

# ADR 0002: Парсинг шрифтов — `skrifa`

**Статус:** пересмотрено 05.10.2026: шрифты парсит `skrifa` (до Спринта 5.5).
Ранее — принято (Фаза 3): `ttf-parser` снят.
**Контекст:** [`Cargo.toml`](../../Cargo.toml), [`crates/pdf/Cargo.toml`](../../crates/pdf/Cargo.toml),
[`crates/render/src/font.rs`](../../crates/render/src/font.rs), [`deny.toml`](../../deny.toml)

## Задача

Метрики глифов нужны, чтобы считать ширину текста: без них не работают ни
перенос строк, ни раскладка колонок, ни PDF-экспорт. ROADMAP §4 называет для
этого `ttf-parser` 0.24 вместе с `rustybuzz` для shaping.

## Решение Фазы 3: снять `ttf-parser` (историческая запись)

### Что изменилось

`ttf-parser` помечен `unmaintained` — RUSTSEC-2026-0192: автор заявил, что
исправлений не будет, и рекомендовал `skrifa` из проекта Google Fonts
(«fontations»). Обновления, которое закрывает вопрос, нет.

При этом в коде парсер шрифтов **не использовался**: зависимость была объявлена
в `doc-converter-pdf`, но встречалась только в доккомментарии. То есть аудит
`cargo deny` падал из-за крейта, который ничего не делал.

### Решение

Зависимость снята, пока она не нужна. Никаких `ignore` в `deny.toml` не
добавлено: незачем оставлять в конфиге исключение для крейта, которого в графе
зависимостей нет.

Выбор между `ttf-parser` (с исключением в аудите) и `skrifa` — решение Фазы 4,
когда метрики понадобятся по-настоящему. К этому моменту будет видно, что
происходит с `rustybuzz`: если он к тому времени сам перешёл на `skrifa` или на
собственный парсер, вопрос решится сам.

### Следствия

- `cargo deny check` чист без исключений — исключение, добавленное «на всякий
  случай», обычно переживает причину, по которой его добавили.
- В `[workspace.dependencies]` запись `ttf-parser` осталась: она не попадает в
  граф зависимостей, пока ни один крейт её не требует, и служит напоминанием о
  плане.
- Фаза 4 обязана принять решение осознанно: молча вернуть `ttf-parser` уже
  нельзя — аудит снова упадёт.

## Пересмотр: берём `skrifa`

ROADMAP v2 требует решить до Спринта 5.5 — метрики текста стоят на этой
зависимости, а Спринт 5.5 закрывает Риск A до PDF и DOCX. Решение: шрифты
парсит `skrifa`.

### Почему `skrifa`

- `ttf-parser` — `unmaintained` без патча: в advisory `patched = []`,
  `informational = "unmaintained"`, а альтернативой назван тот же `skrifa`.
  Крейт, который не получает исправлений, разбирает чужие файлы — а это и есть
  модель угроз просмотрщика.
- Снятие в Фазе 3 убрало только **прямую** зависимость `doc-converter-pdf`. В
  графе `ttf-parser` остался транзитивно: `printpdf → svg2pdf → fontdb/usvg/rustybuzz`.
  Аудит этого не видит, потому что в [`deny.toml`](../../deny.toml) стоит
  `unmaintained = "workspace"` — по этой настройке unmaintained-предупреждения
  срабатывают только на прямых зависимостях членов воркспейса. То есть чистота
  `cargo deny check` здесь — следствие настройки, а не отсутствия крейта в
  дереве; полагаться на неё как на аргумент «можно взять ttf-parser» нельзя.
- `skrifa` уже приходит в дерево транзитивно: `Cargo.lock` фиксирует 0.42.1
  (`printpdf → svg2pdf → subsetter`). Решение не добавляет новых имён в граф —
  оно делает существующее имя прямым и подконтрольным.
- Лицензия `skrifa` — `MIT OR Apache-2.0` (проверено по crates.io). Обе
  лицензии уже в allow-list `deny.toml`, нового исключения не нужно.

### Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| `ttf-parser` с `ignore` в аудите | исключение ради разбора недоверенных файлов — ровно та зависимость, которую нельзя оставлять без патчей |
| Оставить оба варианта открытыми | метрики нужны в Спринте 5.5, а на них стоят Спринты 6, 7, 9, 10; неопределённость в фундаменте дороже выбора |
| **`skrifa`** | выбран: рекомендован самой advisory, живой, уже в дереве, проходит лицензии |

### Что это значит для `rustybuzz`

- В `[workspace.dependencies]` есть `rustybuzz = "0.20"`
  ([`Cargo.toml:52`](../../Cargo.toml)), но как прямую зависимость его не
  подключает ни один крейт: в манифестах `crates/*/Cargo.toml` нет
  `rustybuzz = { workspace = true }`.
- В графе он есть только транзитивно — `printpdf → svg2pdf → usvg → rustybuzz 0.20.1`;
  версия в воркспейсе держится 0.20 именно затем, чтобы не завести вторую копию.
- В коде единственное упоминание — TODO в
  [`crates/render/src/font.rs`](../../crates/render/src/font.rs). Файл не
  объявлен в `lib.rs` и не компилируется (см. ADR-0003), то есть это план, а не
  работающий shaping.
- Решение: `rustybuzz` пока не трогаем — ни прямой зависимостью, ни отказом от
  него. Нужен ли shaping (кернинг, лигатуры) поверх метрик `skrifa`, решает
  ADR-0005; там же определится, становится ли `rustybuzz` прямой зависимостью
  `render`.

### Метрики глифов

Источник ширин — предмет ADR-0005: `advance`, kerning, ascent/descent, кэш,
публичный `render::text_measure`. Здесь фиксируется только парсер: `skrifa`
разбирает TTF/OTF, из его таблиц метрики и берутся. Разделение намеренное —
парсер и политика метрик меняются по разным причинам.

## Следствия

- В `[workspace.dependencies]` появится `skrifa`; версию стоит взять из уже
  приходящей в дерево (в `Cargo.lock` — 0.42.1), иначе в графе окажутся две
  копии — тот же довод, что и у `rustybuzz`. `doc-converter-render` подключит
  её как прямую зависимость в Спринте 5.5.
- `deny.toml` не меняется: лицензия проходит allow-list, `ignore` для `skrifa`
  не нужен. Исключение для `ttf-parser` не добавляется — незачем оставлять в
  конфиге запись ради крейта, которого мы не подключаем. Текущий `ignore` в
  `deny.toml` (`RUSTSEC-2026-0187`) относится к `lopdf` из стека printpdf и к
  шрифтам отношения не имеет.
- Запись `ttf-parser` из `[workspace.dependencies]` к моменту пересмотра уже
  убрана: там остался комментарий, отсылающий к этому ADR. Прямую зависимость
  на `ttf-parser` не заведёт ни один крейт.
- Транзитивный `ttf-parser` из SVG-стека printpdf останется, пока printpdf его
  тянет; убрать его оттуда мы не можем. Наш код от этого не зависит, а
  `unmaintained = "workspace"` не даст этому advisory уронить аудит.
- Срок — до Спринта 5.5: `FontRegistry` обязан стоять на `skrifa`, а не на
  оценочной ширине, иначе `measure_text` из ADR-0005 не на чем построить.

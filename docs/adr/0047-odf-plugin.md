# ADR-0047: ODF-плагин: `.odt`/`.ods`/`.odp` в семейные модели

**Статус:** Принято
**Дата:** 27.10.2026
**Контекст:** To-Be §3.1 (ODF как отдельные модули), M4/M5/M6
**Связанные ADR:** [ADR-0030](0030-format-plugin-traits.md) (trait-слой форматов),
[ADR-0039](0039-cancel-v1-non-goals.md) (отмена non-goal'ов v1),
[ADR-0046](0046-format-plugin-contract.md) (контракт FormatPlugin и семейные модели)

---

## Контекст

- ODF (`OpenDocument` 1.2: `.odt`/`.ods`/`.odp`) числился «в плане» с
  [ADR-0039](0039-cancel-v1-non-goals.md): аудит `docs/architecture.md` держит
  ODF строкой матрицы To-Be («Форматы → DOCX, XLSX, PPTX, ODF»), и ADR-0039
  включил его в задачи Эпика 3. Реализаций до этого решения не было.
- [ADR-0046](0046-format-plugin-contract.md) зафиксировал ключевое правило:
  новый формат — фронтенд уже существующей модели семейства, а не второй
  движок. Раскладка, кадр, PDF, текстовый экспорт и TextLayer берутся у
  семейства; формату остаётся только разбор пакета в эту модель.
- ODF — не OOXML: это ZIP-пакет с частью `mimetype` первой записью (без
  сжатия), каталогом `META-INF/manifest.xml` и частями `content.xml`/
  `styles.xml` в namespace'ах `urn:oasis:names:tc:opendocument:…`. Контейнер,
  каталог и имена частей у трёх форматов общие — различаются тело
  (`office:spreadsheet`/`office:presentation`/`office:text`) и единица рендера
  (лист/слайд/страница), которая у семейств уже есть.

## Решение

1. **Один крейт `crates/odf`, три фичи, общий слой пакета.** Фичи `ods`/`odp`/
   `odt` гейтят форматы; общий `manifest.rs` читает `mimetype` (обязан быть
   первой записью архива) и `META-INF/manifest.xml`, общие `error.rs`/
   `plugin.rs`/`xml.rs` — под `#[cfg]`. Крейт зависит от `core`/`render`/`xlsx`,
   а PPTX-семейство тянет только фича `odp`; `default = []`.
2. **Каждый формат — фронтенд семейной модели (ADR-0046).** ODS →
   [`xlsx::Workbook`](../../crates/xlsx/src/model.rs), ODP →
   [`pptx::Presentation`](../../crates/pptx/src/model.rs), ODT →
   `docx::Document`. Своего layout, painter'а, PDF и текстового экспорта у
   формата-фронтенда нет — всё это у семейства.
3. **Плагины и ошибка.** `OdsPlugin` (`id "ods"`, `Sheets`, `["ods"]`),
   `OdpPlugin` (`id "odp"`, `Slides`, `["odp"]`), `OdtPlugin` (`Pages`,
   `["odt"]`) реализуют `FormatPlugin::info`/`parse` из trait-слоя;
   `OdfError { Core, Malformed, Unsupported, Limit }` отображается в
   `EngineError` (`Unsupported`/`Limit` сохраняют вид, остальное — `Parse`).
4. **Поддержанный срез первого слоя.** ODS: значения всех типов ODF
   (числа/логические/строки; `date`/`time` — серийный номер Excel с числовым
   форматом из `styles.xml`), проценты долей, объединения (spanned/covered),
   повторы строк и столбцов, ширины/высоты, частично числовые форматы
   (`number`/`percentage`/`date`). ODP: слайды `draw:page` и их размер из
   `style:page-layout` мастер-страницы, шейпы (`draw:frame`/`text-box`/`rect`/
   `ellipse`/`custom-shape`), текст с кеглем/цветом/начертанием прогонов,
   заливка/контур шейпов, картинки `draw:image`. ODT — следующий срез
   (текст/заголовки/списки/таблицы/картинки/page-layout), здесь только
   зафиксирован как фича. Явные TODO: полные стили ячеек ODS (шрифт/заливка/
   рамки), print settings, маркеры списков (ODP/ODT), диаграммы, темы.
5. **Неподдержанное не роняет документ.** ODP копит пропущенное в
   `Presentation::warnings` (с потолком `MAX_WARNINGS`), ODS пропускает
   неизвестные элементы молча, сохраняя значение (формулы — текстом, вложенные
   таблицы — пропуском). `Unsupported` — только когда `mimetype` пакета
   принадлежит другому ODF-виду или чужому ZIP. Лимиты: `ZipLimits` по
   умолчанию (ADR-0015) и `MAX_ROW`/`MAX_COL`/`MAX_CELLS_PER_SHEET` (1 048 576)
   на повторы.
6. **Публичный API и wasm/TS/CLI — отдельными шагами.** Это решение фиксирует
   только Rust-слой разбора в семейные модели; ленивые wasm-пакеты, воркеры,
   фабрики `createOdt/Ods/OdpViewer` и бюджеты `.size-limit.mjs` — будущие
   ADR/задачи по чек-листу ADR-0046.

## Альтернативы

- **Собственный layout/рендер для ODF** — отвергнуто: дублирует табличную
  раскладку, перенос строк, PDF-бэкенд и текстовый экспорт; расхождения между
  «своим» и семейным путём давали бы разные страницы у одного документа
  (ADR-0046).
- **Отдельные крейты `odt`/`ods`/`odp`** — отвергнуто: контейнер, каталог
  `manifest.xml` и ошибки общие, а `PackageKind` и `manifest.rs` держат их
  одним модулем; три крейта размножили бы этот слой без выигрыша.
- **Внешний парсер ODF** (LibreOffice/lo, сторонние крейты) — отвергнуто:
  лицензия/размер и несовместимость с wasm-сборкой; движок и так уже умеет
  раскладку семейств, нужен только разбор в их модель.

## Последствия

- Feature-гейтинг: `ods`/`odp`/`odt` разводят форматы и зависимости; ODP тянет
  PPTX-семейство (`pptx`, `pptx-layout`, `pptx-render`) только своей фичей,
  поэтому первый срез ODS не раздувает сборку.
- Фикстуры `test-fixtures/odf/` (генератор `scripts/generate_odf_fixtures.ts`,
  детерминированный ZIP): `ods/{simple,repeated}.ods`,
  `odp/{simple,text_styles}.odp` и заранее заготовленные `odt/*`. Пакеты —
  ODF 1.2 с `mimetype` первой записью без сжатия.
- Тесты: сквозные `crates/odf/tests/{ods,odp}.rs` на фикстурах плюс собранные
  в памяти битые пакеты (нет `mimetype`/`manifest.xml`/`content.xml`, чужой
  mimetype, противоречие корня каталога, гигантские повторы); inline-тесты
  плагина, ошибки и форматов.
- Ограничения первого слоя остаются: формулы без пересчёта и без перевода в
  A1-синтаксис, вложенные таблицы пропускаются, скрытые листы видимы,
  `custom-shape` сводится к прямоугольнику, тема — `Theme::default()`, маркеры
  списков не разрешаются, анимации/переходы/диаграммы не поддержаны.
- Бюджеты wasm и строка в `.size-limit.mjs` появляются вместе с wasm-слоем —
  не в этом решении.

# ADR-0027: Реестры npm — npmjs.org основной, GitHub Packages зеркало

**Статус:** Принято 21.10.2026.
**Связанные ADR:** [ADR-0026](0026-rust-crates-distribution.md) (дистрибутив
Rust-крейтов; этим ADR не пересматривается).

## Контекст

- npm-пятёрка `@meerrec/*@1.0.0` опубликована только в **GitHub Packages**
  этого репозитория. В `registry.npmjs.org` публикации нет: организации
  `@meerrec` на npmjs.org ещё не существует.
- GitHub Packages требует авторизацию даже на чтение: для установки нужен
  personal access token с `read:packages`. Для внешнего потребителя это
  барьер входа, а npmjs.org ставится без токена и настройки реестра.
- `.github/workflows/release.yml` уже содержит шаг публикации в npmjs.org, но
  он выключен по умолчанию (`vars.PUBLISH_TO_NPMJS`) и стоит после GitHub
  Packages; preflight внешних предпосылок отсутствует.
- Версии в npmjs.org неизменяемы: опубликованную версию нельзя перезаписать
  или удалить. Это делает порядок реестров и проверки до публикации частью
  решения, а не деталью реализации.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Оставить только GitHub Packages | Публичный реестр с обязательной авторизацией на чтение — барьер для adoption; npmjs.org остаётся целевым |
| Перейти только на npmjs.org, GitHub Packages убрать | Теряется действующее зеркало и запасной путь установки; GitHub Packages уже работает и не мешает основной публикации |
| Публиковать в оба реестра одним шагом без переключения скоупа | `setup-node` пишет в `~/.npmrc` `@meerrec:registry=https://npm.pkg.github.com`; скоуп-реестр важнее флага `--registry`, и npmjs-публикация молча ушла бы в GitHub Packages (или упала на авторизации) |
| **Выбран:** dual-publish — npmjs.org основной, GitHub Packages зеркало | Публичный реестр без барьера входа плюс сохранённое рабочее зеркало; откат и повторный запуск предсказуемы |

## Решение

1. **npmjs.org — основной публичный реестр**, GitHub Packages — действующее
   зеркало. Публикуются оба (dual-publish), состав пакетов и версии совпадают.
2. **Порядок публикации: npmjs.org первым, GitHub Packages вторым.** Основной
   реестр не должен зависеть от состояния зеркала. Если публикация в npmjs.org
   упала, GitHub Packages в этом прогоне не обновляется.
3. **Скоуп-реестр переключается явно.** `actions/setup-node` с
   `registry-url` и `scope` пишет `@meerrec:registry` в `~/.npmrc`; этот
   скоуп-реестр важнее флага `--registry`. Поэтому:
   - preflight и npmjs-публикация выполняют
     `npm config set @meerrec:registry https://registry.npmjs.org/`;
   - шаг GitHub Packages явно возвращает
     `npm config set @meerrec:registry https://npm.pkg.github.com/`.
4. **`publishConfig.registry` в `package.json` не добавляется.** Он прибил бы
   пакет к одному реестру и сломал dual-publish; выбор реестра остаётся за
   `--registry` и скоупом в `~/.npmrc`.
5. **crates.io — за выключателем `vars.PUBLISH_CRATES_IO`** (по умолчанию
   выключен). Публикация Rust-крейтов остаётся non-goal v1.x по ADR-0026;
   отсутствие валидного `CARGO_REGISTRY_TOKEN` не должно валить релиз уже
   после успешной публикации npm-пакетов.
6. **Ручные внешние предпосылки** (в коде не создаются):
   - организация `@meerrec` зарегистрирована на npmjs.org;
   - выпущен granular/automation token с правом publish в эту организацию и
     обходом 2FA;
   - токен положен в секрет репозитория `NPM_TOKEN`;
   - переменная репозитория `PUBLISH_TO_NPMJS=true`.
7. **Preflight npmjs.org выполняется до `changeset version`**: `npm whoami`
   по npmjs.org с `NPM_TOKEN`. При ошибке шаг падает с сообщением про
   отсутствующую организацию `@meerrec` или нехватку прав publish — релиз не
   проходит половину пути.
8. **Первый publish — токеном.** OIDC/trusted publishing переключается со
   следующего релиза, когда trusted publisher будет настроен на npmjs.org;
   после этого секрет `NPM_TOKEN` из workflow убирается.
9. **Версии на npmjs.org неизменяемы.** Откат — `npm deprecate` с указанием
   версии и причины; удаление (`npm unpublish`) и перезапись той же версии не
   используются. Повторный запуск релиза пропускает уже опубликованные версии.
10. **Метаданные публикации.** У всех пяти пакетов есть `repository`
    (`type`, `url`, `directory`), `homepage`, `bugs` и `license`; в каждом
    тарболе лежат `LICENSE` (побайтово равен корневому) и `README.md`.
    Проверки: `scripts/check-package-metadata.mjs` и `npm pack preflight` в
    `release.yml`.

## Следствия

- **Документация до реальной публикации** формулирует так: «npmjs — целевой
  основной реестр (публикация готовится), GitHub Packages — действующее
  зеркало». Установка пока идёт из GitHub Packages; после первой публикации
  в npmjs.org основной командой станет `npm install @meerrec/*` без токена.
- **Release не ломается без npmjs:** при `PUBLISH_TO_NPMJS` не равном `true`
  публикация в GitHub Packages идёт как раньше, npmjs-шаги пропускаются.
- **Частичный сбой npmjs-публикации** лечится повторным запуском джобы:
  опубликованные версии определяются через `npm view` и пропускаются.
- **Зеркало может отставать:** если шаг GitHub Packages упадёт после успешной
  публикации в npmjs.org, основной реестр уже содержит версию, а зеркало
  догоняется повторным запуском.
- **Откат не удаляет версию:** `npm deprecate` помечает её предупреждением,
  но она остаётся доступной для установки по точной версии.
- **ADR-0026 остаётся в силе:** crates.io по-прежнему non-goal v1.x, его шаг
  лишь получил отдельный выключатель.

## Пересмотр

Пересмотр — новым ADR, если: (1) первая публикация в npmjs.org состоялась и
документация переведена на npmjs как основной путь установки; (2) включён
OIDC/trusted publishing и токен больше не используется; (3) GitHub Packages
перестаёт быть зеркалом или npmjs.org перестаёт быть основным реестром.

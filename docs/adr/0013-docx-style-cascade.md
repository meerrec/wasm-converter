# ADR-0013: Каскад стилей DOCX

**Статус:** Принято
**Дата:** 05.10.2026
**Контекст:** проектирование модели DOCX перед Спринтом 8
**Связанные ADR:** ADR-0003, ADR-0005, ADR-0018

## Контекст

WordprocessingML определяет применение форматирования как каскад: одни и те же свойства могут быть заданы на семи уровнях, побеждает последний применённый (ECMA-376 Part 1 §17.7). Большинство парсеров реализуют его неполно — «paragraph style + direct formatting» — и получают документы, которые выглядят не так, как в Word.

Каскад можно резолвить на парсинге (модель хранит нормализованные свойства) или на layout (модель хранит сырые + ссылки). Выбор влияет на размер модели, возможность переопределения в Спринте 9, тестируемость, будущее редактирование.

## Решение

### 1. Каскад резолвится на layout (Спринт 9), не на парсинге (Спринт 8)

Модель несёт `RawPPr` и `RawRPr` плюс ссылки на стили. На парсинге только: разрешение `StyleId` → `Style`, `NumId` → `Num` → `AbstractNum`, детектирование циклического `basedOn`.

Причины:

- размер модели: нормализованный параграф — ~40 полей вместо ~10;
- layout применяет каскад в контексте (внутри таблицы, списка, секции);
- snapshot-тесты стабильны: `RawPPr`/`RawRPr` отражают входной XML;
- задел под редактирование: direct formatting — отдельный слой.

### 2. Полный порядок каскада

#### pPr

```
1. docDefaults
2. Table style (если абзац внутри ячейки)
3. Numbering level properties
4. Paragraph style chain (basedOn рекурсивно)
5. Direct paragraph formatting
```

#### rPr

```
1. docDefaults
2. Table style
3. Numbering level properties
4. Paragraph style's rPr
5. Character style chain
6. Direct run formatting
```

`w:rPr` внутри `w:pPr` (mark run properties) применяется к знаку абзаца, не к runs. В модели — `Paragraph::mark_rpr`.

### 3. `basedOn` — рекурсивно, с защитой

- Глубина ≤ 32.
- Цикл → `ParseWarning::CyclicBasedOn`.
- Отсутствующий `basedOn` → `ParseWarning::MissingStyleRef`.
- `w:link` не участвует в цепочке `basedOn`; применяется отдельно при resolve.

### 4. Toggle — тринстейт

```rust
enum Toggle { On, Off, Inherit }
```

- отсутствие → `Inherit`;
- `w:val="1"`/`"true"`/отсутствует → `On`;
- `w:val="0"`/`"false"` → `Off`.

Boolean ломает документы, где style включает `w:b`, а direct formatting выключает через `w:val="0"`.

### 5. Условные форматы таблиц

`w:tblStylePr` с `w:type`: `firstRow`, `lastRow`, `firstCol`, `lastCol`, `band1Horz`, `band2Horz`, `band1Vert`, `band2Vert`, `nwCell`, `neCell`, `swCell`, `seCell`.

Порядок (ECMA-376 §17.7.6):

```
wholeTable → band1Horz → band2Horz → band1Vert → band2Vert →
firstCol → lastCol → firstRow → lastRow → nwCell → neCell → swCell → seCell
```

Позже применённый побеждает. Условные форматы применяются, если в `w:tblLook` флаг включён.

### 6. Что НЕ делает каскад

- Не генерирует `w:lvlText`.
- Не вычисляет поля (`PAGE`, `TOC`, `REF`).
- Не применяет `w:compat`.
- Не нормализует единицы.

## Последствия

### Положительные

- Модель компактна.
- Спринт 9 не переписывает модель.
- Snapshot-тесты стабильны.
- Каскад тестируется отдельно.
- Задел под редактирование.

### Отрицательные

- Спринт 9 сложнее (+3–5 дней).
- Резолвинг многократный, нужен кэш по `(StyleId, контекст)`.
- Отладка сложнее.

## Альтернативы

- **A. Резолвить на парсинге.** Отклонено: модель ×3–5, layout не переопределяет, снапшоты шумные.
- **B. Гибрид.** Отклонено: хуже обоих крайних.
- **C. Computed-свойства обратно в модель.** Отклонено: дублирование источника истины.

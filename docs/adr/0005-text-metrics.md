# ADR 0005: Источник ширин текста — `skrifa` + таблицы шрифта

**Статус:** принято 05.10.2026; реализация — Спринт 5.5
**Контекст:** [`crates/xlsx/src/paint.rs`](../../crates/xlsx/src/paint.rs),
[`crates/xlsx/src/layout.rs`](../../crates/xlsx/src/layout.rs),
[`crates/render/src/font.rs`](../../crates/render/src/font.rs),
[`crates/render/src/painter/text.rs`](../../crates/render/src/painter/text.rs),
[`crates/pdf/src/lib.rs`](../../crates/pdf/src/lib.rs)

## Задача

Настоящие метрики текста — фундамент, а не одна из задач: от них зависят

- перенос по словам в DOCX-layout (Спринт 9);
- `#####` для числа, не влезшего в узкий столбец XLSX (уже работает, но по
  оценке);
- PDF-экспорт: `pdf/src/text.rs` меряет и переносит тем же кодом, что canvas
  (Спринт 6), иначе точки разрыва разъедутся;
- hit-testing по тексту — выделение и курсор (сегодня его нет);
- пагинация (Спринт 7).

Расхождение оценок здесь не косметика: перенос строк — это то, что видно
пользователю, и то, что DOCX-поток и PDF обязаны делать одинаково. Сейчас
источника ширин нет — есть таблица, подогнанная под один шрифт и один вид
текста.

## Контекст: где ширина считается сейчас

- [`xlsx::paint::estimate_width`](../../crates/xlsx/src/paint.rs) (стр. 700) —
  единственный источник ширины текста: оценка по таблице «Calibri 11» — цифра 7.0 пикселя,
  `.`/`,`/пробел — 3.5, `-`/`+`/`/`/`:` — 4.0, всё прочее — 7.5, с множителем
  `size / (11 · PX_PER_POINT)`. Функция вызывается в `draw_text` (стр. 646)
  ровно для одного решения: если `CellValue::Number` шире ячейки, вместо числа
  рисуется `HASHES` = `"#####"` (стр. 690). Для чисел этого достаточно (цифры
  Calibri моноширинные, вся система ширин Excel стоит на ширине нуля), для
  произвольного текста — нет.
- [`xlsx::layout`](../../crates/xlsx/src/layout.rs) держит `MAX_DIGIT_WIDTH =
  7.0` и `width_to_px` — но это **единица ширины столбца из формата** («сколько
  символов `0` основного шрифта помещается»), а не измерение текста. Она
  остаётся в `xlsx` и после появления метрик; учёт настоящего шрифта книги
  меняет в ней коэффициент, а не место.
- `FontRegistry` в [`crates/render/src/font.rs`](../../crates/render/src/font.rs)
  описан, но в путь рисования **не подключён, потому что не компилируется**:
  файл не объявлен в [`crates/render/src/lib.rs`](../../crates/render/src/lib.rs),
  а `lru`, на который он ссылается, отсутствует в графе зависимостей (`cargo
  tree -i lru` не находит пакета при том, что запись в `[workspace.dependencies]`
  есть). Его `measure` — заглушка: `width = число_символов · size · 0.55`,
  ascent 0.8, descent 0.2, line_height 1.2, с TODO «реальные метрики через
  ttf-parser + rustybuzz». То есть в проекте нет не только подключённого
  реестра, но и самого типа в собранном виде.
- Как текст доходит до canvas сегодня: `draw_text` кладёт в
  `DrawCommand::Text` гарнитуру (имя семейства строкой в пуле), кегль, цвет,
  выравнивание и флаги `bold`/`italic`; painter собирает CSS-описание шрифта
  ([`PaintState::font_css`](../../crates/render/src/painter/state.rs)) и зовёт
  `fill_text` ([`painter_2d.rs`](../../crates/render/src/painter/painter_2d.rs),
  стр. 166). Меряет и раскладывает текст сам canvas — в кадре ширин нет.
- `render::painter::text::ellipsize` ([`text.rs`](../../crates/render/src/painter/text.rs))
  уже принимает меряющую функцию замыканием — ему нужен только настоящий
  измеритель.
- Потребители пока пусты: [`pdf`](../../crates/pdf/src/lib.rs) — `todo!()`,
  [`docx`](../../crates/docx/src/lib.rs) — заглушка. Спринт 5.5 — последний
  момент поставить метрики до того, как на них начнут опираться PDF и DOCX.
- Hit-testing текста отсутствует: `xlsx::paint::hit_test` возвращает ячейку, а
  в [`protocol.ts`](../../packages/core/src/protocol.ts) тип
  `HitResult = CellRef | TextPos` с `TextPos { kind: 'text', page, offset }`
  объявлен, но ничто его не производит.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Достроить таблицу `estimate_width` | для чисел работает, для произвольного текста нет; перенос DOCX и PDF на такой оценке разойдётся |
| `ctx.measureText` из canvas как единственный источник | доступен только в воркере с OffscreenCanvas; нативный PDF-экспорт остаётся без метрик, и точки разрыва canvas/PDF разъезжаются |
| Средние ширины (0.5 em) | не проходит по `#####`: Excel считает по ширине нуля, а не по средней |
| **`skrifa` + таблицы шрифта + LRU-кэш** | выбран |

## Решение

- Парсер — `skrifa` (ADR-0002). Из таблиц шрифта берутся advance
  (горизонтальное продвижение глифа), кернинг и ascent/descent — последние
  нужны для базовой линии и межстрочного интервала, то есть для `TextBaseline`
  и высоты строки.
- Кэш — LRU по `(font_id, glyph_id, size)`: кэшируется метрика одного глифа,
  ширина строки собирается суммой. Кернинг и лигатуры — надстройка над суммой;
  нужен ли для неё shaping и остаётся ли `rustybuzz` прямой зависимостью,
  решается вместе с реализацией (ADR-0002).
- Публичный API — `render::text_measure`:
  - `measure_text(text, font, size) -> Width`;
  - `break_lines(text, font, size, max_width) -> Vec<Range>`.
- Замена оценки: `xlsx::paint::estimate_width` удаляется, проверка `#####`
  зовёт `measure_text`. Правило о числах остаётся в `xlsx::paint` — меняется
  только источник ширины.
- Canvas и PDF используют один и тот же источник: painter — через `render`,
  PDF-экспорт — через тот же `render::text_measure`, без второй реализации.
- `FontRegistry` переезжает из осиротевшего файла в объявленный модуль
  `render::font` и подключается в путь рисования. Отображение «имя семейства в
  `DrawCommand::Text` → `FontId` реестра» придётся определить: сегодня команда
  несёт имя, а реестр ключуется `FontId = u32`.

## Следствия

- Единые точки разрыва: canvas (Спринт 5.5) и PDF (`pdf/src/text.rs`, Спринт 6)
  считают одним кодом — DoD Спринта 6 это и проверяет («canvas и PDF дают
  одинаковые точки разрыва»).
- Бюджет ROADMAP §9: `measure_text` на 100 символов — < 1 мкс native и < 5 мкс
  WASM. Кэш — способ в него уложиться: повторные глифы не считаются заново,
  строка собирается суммой кэшированных advance'ов.
- Срок — Спринт 5.5; его DoD требует «`FontRegistry` подключён,
  `estimate_width` удалён».
- Что удаляется из `xlsx`: `paint.rs::estimate_width` и таблица
  7.0/3.5/4.0/7.5. `#####` остаётся — это правило Excel, а не метрика.
  `MAX_DIGIT_WIDTH` и `width_to_px` в `xlsx::layout` остаются: это определение
  ширины столбца в формате.
- `lru` из `[workspace.dependencies]` наконец попадает в граф — как зависимость
  `render`; `TextMetrics`/`font.rs` перестают быть мёртвым файлом.
- За рамками ADR остаётся политика подстановки, если шрифта книги нет в
  реестре: сейчас реестр принимает байты явно (`register`), а откуда они
  берутся и что рисовать при промахе — вопрос Спринта 5.5, не метрик.

# ADR-0026: Дистрибутив Rust-крейтов — GitHub Packages и ассеты релиза, crates.io — non-goal

**Статус:** Принято 15.10.2026.
**Связанные ADR:** [ADR-0023](0023-libreoffice-wasm-exact-backend.md) (no-go как норма решения),
[ADR-0025](0025-xlsx-layout-boundary.md) (границы крейтов не меняются).

## Контекст

Версии шести крейтов и пяти npm-пакетов — `1.0.0`; публикация — последний
открытый пункт релиза (ROADMAP §12). Фактическое состояние на 15.10.2026:

- **npm-часть уехала.** Пять пакетов — `@meerrec/core`, `@meerrec/wasm`,
  `@meerrec/wasm-docx`, `@meerrec/wasm-pdf`, `@meerrec/cli`, версия `1.0.0` —
  опубликованы в **GitHub Packages** этого репозитория (`npm.pkg.github.com`,
  скоуп совпадает с владельцем). В `registry.npmjs.org` публикации нет: там нет
  ни скоупа `@doc-converter` (исходное имя), ни организации `@meerrec`. Шаг
  публикации в npmjs.org оставлен в `release.yml` за выключателем
  `vars.PUBLISH_TO_NPMJS` и по умолчанию выключен.
- **Попытка публикации в crates.io упёрлась в токен.** Шаг `crates.io publish`
  упал на первом же крейте: `401 Unauthorized` — «The given API token does not
  match the format used by crates.io». Секрет `CARGO_REGISTRY_TOKEN` содержит
  токен неверного формата; починка — новый токен с https://crates.io/me.
- **Ставить из реестра нечего.** В workspace нет ни одного `[[bin]]` и ни одного
  `src/main.rs`: единственные бинари — восемь fuzz-таргетов в `crates/fuzz`, а
  это отдельный workspace с `publish = false`. То есть `cargo install` по любому
  из шести публикуемых крейтов не поставил бы ничего: CLI проекта — Node-пакет
  `@meerrec/cli` (bin `doc-converter` → `dist/cli.js`), не Rust-бинарь.
- **Потребителей из реестра нет.** Внутренние зависимости крейтов объявлены как
  `{ workspace = true }` (в корневом манифесте — path + версия); внешних
  потребителей `doc-converter-*` из crates.io не существует: это библиотеки
  вьюера, их зовут свои же крейты.
- **`LICENSE` в `.crate` не попадает.** Текст лицензии лежит в корне
  репозитория, а cargo включает файлы `LICENSE*` только из каталога пакета:
  в каждом из шести собранных `.crate` файлов `LICENSE` — ноль.
- **Имена на crates.io свободны:** все восемь (`doc-converter-core`,
  `-render`, `-xlsx`, `-docx`, `-pdf`, `-wasm`, `-pdf-wasm`, `-docx-wasm`)
  отвечали 404 — решения на будущее ничем не ограничены.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Починить `CARGO_REGISTRY_TOKEN` и опубликовать шесть крейтов, как планировалось в Спринте 12 | Потребителей нет и `cargo install` ставить нечего, а первый релиз необратим: версии с crates.io не удаляются. Имена свободны — токен можно завести позже без потерь |
| Опубликовать как есть, зная про отсутствие `LICENSE` в архивах | Дистрибутив под Apache-2.0 без текста лицензии — не то, что стоит фиксировать в реестре |
| Не публиковать Rust вообще и не раскладывать архивы | Rust-часть осталась бы доступной только из репозитория, без готовых артефактов |
| **Выбран:** дистрибутив = GitHub Packages (npm-пятёрка) + ассеты релиза | Пользователь получает и готовые npm-пакеты, и архивы крейтов; crates.io не занимается ложными версиями |

## Решение

1. Rust-крейты `doc-converter-*` **в crates.io не публикуются в v1.x** — это
   осознанный non-goal, а не отложенная задача.
2. Дистрибутив v1.0.0 — пять npm-пакетов `@meerrec/*@1.0.0` в GitHub Packages
   этого репозитория плюс ассеты релиза
   [`v1.0.0`](https://github.com/meerrec/wasm-converter/releases/tag/v1.0.0):
   `meerrec-*.tgz` (пять npm-тарболов), `doc-converter-*.crate` (шесть архивов
   крейтов) и `SHA256SUMS.txt` с контрольными суммами архивов.
3. `.crate`-архивы собираются тем же способом, что в dry-run-джобе
   (`cargo package --no-verify` по шести крейтам) в чистом клоне тега; резолвинг
   внутренних зависимостей, которых ещё нет в реестре, обеспечивается
   `--config patch.crates-io.*` — на нормализованный манифест внутри архива это
   не влияет (зависимости там остаются версиями).
4. Шаг `crates.io publish` из `release.yml` не удаляется: он остаётся на месте
   и не выполняется по факту отсутствия валидного токена, а не по решению кода.

## Следствия

- **docs.rs не появится.** Упоминания docs.rs в списках документации — следствие
  публикации в реестре; без неё публичная документация — `docs/api/` (TypeDoc)
  плюс rustdoc из исходников.
- **Rust-потребителю нужна ручная работа:** `[patch.crates-io]` с локальными
  путями, source replacement на зеркало или сборка из репозитория; `cargo add
  doc-converter-*` не сработает.
- **npm-потребитель** ставит пакеты из GitHub Packages: `@meerrec:registry` и
  токен с `read:packages` в `~/.npmrc` (корневой README, «Установка»);
  альтернатива — тарболы из ассетов релиза.
- **Имена `doc-converter-*` на crates.io остаются свободными** — публикация в
  будущем возможна без конфликтов.
- `cargo package` и `cargo publish --dry-run` в dry-run-джобе остаются: они
  проверяют упаковку и метаданные, ничего не публикуя.

## Пересмотр

Пересмотр — только новым ADR и только при выполнении обоих условий:
(1) появился **реальный** потребитель Rust-крейтов из реестра (не гипотетический);
(2) заведён валидный `CARGO_REGISTRY_TOKEN` (новый токен с https://crates.io/me) и
решён вопрос с текстом `LICENSE` внутри `.crate`.

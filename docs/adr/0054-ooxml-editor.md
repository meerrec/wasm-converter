# ADR-0054: Локальный OOXML-редактор — patch исходного ZIP в отдельном Worker

**Статус:** Принято
**Дата:** 18.11.2026
**Контекст:** требование сделать все команды ленты примера рабочими, включая
форматирование, структурные правки, undo/redo и сохранение DOCX/XLSX/PPTX
**Связанные ADR:** [ADR-0018](0018-editing-boundaries.md),
[ADR-0020](0020-parser-writer-boundary.md),
[ADR-0043](0043-runtime-text-edits.md)

---

## Контекст

ADR-0018 запрещал editing-инфраструктуру, ADR-0020 — writer, а ADR-0043
разрешил только текстовые правки в рантайме без записи файла. Теперь продукт
явно требует редактирования с сохранением: это триггер пересмотра обоих
ранних решений.

Round-trip через нормализованную модель потерял бы неизвестные элементы,
`rsid`, порядок атрибутов и части пакета, которые просмотрщик не читает.
Разбор OOXML и тяжёлые изменения на main-потоке блокировали бы интерфейс.

## Решение

1. **Редактор примера — отдельный Web Worker.** React владеет только выбором,
   диалогами и view state. Исходные байты, XML-документы, история и генерация
   результата живут в editor-worker; существующий Rust/WASM viewer остаётся
   единственным источником раскладки и кадра.
2. **Writer — адресный patch исходного ZIP.** JSZip сохраняет все part'ы;
   `@xmldom/xmldom` меняет только затронутые XML. Неизвестные элементы и
   непрочитанные part'ы не проходят через нормализованную модель и не
   выбрасываются. Сериализация XML не обещает побайтовую идентичность
   изменённого part'а, но обязана сохранять его семантику и namespace'ы.
3. **После команды документ открывается заново.** Worker возвращает новые
   байты, страница передаёт их существующему viewer. Поэтому canvas, TextLayer,
   PDF и сохранённый OOXML видят одно содержимое; отдельной JS-раскладки нет.
4. **История — снимки пакета в Worker.** Каждая успешная мутация атомарна:
   сначала новый пакет проходит сериализацию, затем попадает в текущее
   состояние. Undo/redo возвращают снимки целиком; открытие другого документа
   очищает историю. Ошибка команды не меняет текущий документ.
5. **Сохранение — настоящий OOXML.** «Сохранить» скачивает текущие байты с
   исходным расширением и MIME. Печать и sharing используют PDF из viewer;
   текстовые экспорты остаются отдельными командами.
6. **Без внешних сервисов.** Документ, шрифтовые и языковые операции не уходят
   в сеть. Проверка правописания использует нативный `spellcheck` браузера в
   редактируемом поле; пользователь сам подтверждает применение исправлений.
7. **Граница изменения — пример.** Публичный протокол `@meerrec/core`,
   DisplayList, Rust-модели и транспорт кадра не меняются. Перенос редактора в
   публичный пакет потребует отдельного API-ревью.

## Рассмотренные варианты

- **Round-trip через `docx`/ExcelJS/PptxGenJS** — отклонено: библиотеки не
  сохраняют произвольный исходный пакет и создают вторую нормализованную
  модель, а PPTX-чтения у генераторов нет.
- **Rust writer по нормализованной модели** — отклонено для этого среза:
  потерял бы неизвестные данные и потребовал бы сериализации всей модели.
- **DOM-редактор поверх canvas** — отклонено: дал бы вторую геометрию и
  разошёлся бы с PDF и TextLayer.
- **Редактирование на main** — отклонено: ZIP и XML больших документов
  блокировали бы ввод и прокрутку.

## Последствия

- Появляются две runtime-зависимости примера: JSZip и `@xmldom/xmldom`; обе
  выполняются в отдельном чанке editor-worker и не попадают в основной бандл.
- Каждая правка требует повторного разбора документа viewer'ом. Это осознанная
  цена единой раскладки; оптимизация инкрементальным протоколом возможна только
  новым ADR.
- История потребляет память пропорционально размеру пакета и числу снимков;
  лимит истории и отмена команд обязаны быть частью реализации.
- Обязательная проверка: изменённый файл повторно открывается viewer'ом,
  сохраняется с исходным расширением, undo/redo восстанавливает содержимое,
  исходные неизменённые part'ы остаются в ZIP.

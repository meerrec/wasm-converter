# ADR-0041: TextLayer и DOM-overlay — доступность без изменения `DisplayList`

**Статус:** Принято
**Дата:** 22.10.2026
**Контекст:** Спринт 2 (a11y): выделение, копирование и скринридеры для
просмотрщика DOCX; `DisplayList` v4 — контракт кадра между wasm и painter
(`docs/architecture.md`, §«Рендер»)
**Связанные ADR:** [ADR-0003](0003-render-boundary.md) (граница `render`),
[ADR-0029](0029-main-thread-render-backend.md) (рендер на main-потоке),
[ADR-0040](0040-bidi-strategy.md) (логический reading order и RTL-строки)

---

## Контекст

- Canvas даёт только пиксели: текст недоступен скринридеру, выделению и
  копированию. Для доступности нужен текстовый слой с координатами строк.
- `DisplayList` — проводной формат кадра (`DL_VERSION = 4`) между wasm и
  painter, в том числе в SAB-транспорте. Добавление текста в него изменило бы
  формат и painter, а браузер всё равно шейпит строку сам.
- Раскладка уже считает прямоугольники строк (`Line` в
  `crates/docx/src/layout/paragraph.rs`, `CellLine` в
  `crates/docx/src/layout/tables.rs`), но хранит только склеенный текст и
  стиль строки — без диапазонов исходного текста и разбиения на фрагменты.
  Второй геометрии (отдельно для DOM) быть не должно: она разойдётся с
  canvas.

## Решение

1. **TextLayer — параллельный выход раскладки, не `DisplayList`.**
   `DisplayList` v4 и painter не меняются; текстовый слой собирается из тех
   же результатов раскладки, что и кадр.
2. **Раскладка отдаёт фрагменты.** В `Line` и `CellLine` добавляется
   `fragments: Vec<LineFragment>`; `LineFragment` — байтовый диапазон в
   тексте абзаца, `x`, `width`, стиль. Выход TextLayer — `TextRun
   { bbox, line_rect, text, style, direction, page, node_id }`. `bbox` и
   `line_rect` берутся из раскладки: другой геометрии нет.
3. **TS-слой.** Прозрачный DOM-слой лежит поверх canvas внутри scroller;
   координаты — из раскладки, `transform: translate(padLeft, 0) scale(zoom)`.
   Виртуализация по страницам окна ±1: DOM строится только для страниц,
   близких к видимым. Визуальные spans — по одному на строку: браузер шейпит
   строку целиком, пофрагментные spans разорвали бы арабское соединение.
   Семантическое дерево строится один раз на документ, `user-select: none`,
   и служит для AT.
4. **Копирование — кастомный сериализатор.** Выделение не отдаётся
   браузерному `Selection`: сериализатор собирает текст из модели и
   раскладки. Таблица копируется как TSV по логическим `row`/`col`;
   Ctrl+A выделяет весь документ.
5. **a11y — opt-in, по умолчанию выключен.** При включении canvas получает
   `aria-hidden`, контейнер — `role="document"`, узлы дерева — роли
   `paragraph`, `heading`, `table`, `row`, `cell`, `columnheader`.
6. **XLSX в Спринте 2** — только минимальная a11y-обвязка (роли
   контейнера и canvas, подпись листа), без text-layer: ячеек в DOM не
   появляется.

## Рассмотренные варианты

- **Добавить текст в `DisplayList`** — меняет проводной формат и painter,
  дублирует браузерный шейпинг; отклонено.
- **Spans по фрагментам** — точнее для выделения, но рвёт арабское
  соединение и раздувает DOM; одна строка на span выбрана осознанно.
- **Нативное `contenteditable`/браузерное выделение** — неустойчиво на
  стыке страниц и при зуме, не умеет TSV для таблиц; отклонено.
- **Рисовать текст только DOM вместо canvas** — метрики разойдутся с
  canvas/PDF и сломают контракт кадра; отклонено.

## Последствия

- У раскладки два выхода (кадр и TextLayer), которые обязаны оставаться
  синхронными; тесты сверяют `bbox` TextRun с прямоугольником строки в
  `DisplayList`.
- DOM-слой следует за скроллом и зумом через `transform`, без пересчёта
  геометрии и без новой раскладки.
- Выделение визуально построчное (spans по строкам), но копирование точное:
  его даёт сериализатор, а не DOM `Selection`.
- Текст дублируется в памяти (строки кадра + DOM); opt-in и виртуализация
  окна ±1 ограничивают цену.
- Семантическое дерево требует маппинга заголовков (уровень outline из
  стиля) и таблиц из модели; XLSX остаётся canvas-only до отдельного
  решения.

# ADR 0001: Раскладка ячеек листа — CSR

**Статус:** принято (Фаза 3, шаг 3)
**Контекст:** `crates/xlsx/src/model.rs`

## Задача

Хранить ячейки листа так, чтобы:

- разрежённость не стоила памяти (типовой лист — единицы процентов заполнения,
  лимит Excel — 1 048 576 строк × 16 384 столбца);
- укладываться в бюджет «память < 2× размера файла» (`ROADMAP.md` §9);
- быстро отдавать строку целиком — именно так рендер берёт видимую область;
- находить ячейку по адресу `CellRef`.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| `HashMap<(u32, u32), Cell>` | порядок обхода теряется, хеш-заголовки и пробирование дают ×3–4 к памяти |
| `Vec<Vec<Cell>>` | миллион пустых `Vec` — 24 байта на строку только за факт существования |
| `Vec<Row>`, `Row { index, cells: Vec<Cell> }` | одна аллокация на строку: на 100k строк это 100k мелких блоков |
| **CSR** | выбран |

## Решение

Три массива в [`Worksheet`](../../crates/xlsx/src/model.rs):

- `row_ids: Vec<u32>` — номера **непустых** строк по возрастанию;
- `row_starts: Vec<u32>` — начало строки `i` в `cells`; длина совпадает с `row_ids`;
- `cells: Vec<Cell>` — ячейки всех строк подряд, внутри строки — по возрастанию
  столбца.

Конец строки `i` — это `row_starts[i + 1]`, а у последней строки — длина `cells`.
Sentinel-элемент в `row_starts` не хранится: он потребовал бы конвертации длины
массива в `u32` при каждом завершении листа.

Ячейка хранит только `col`; номер строки выводится из позиции в CSR, поэтому
рассинхрон «ячейка помнит не свою строку» невозможен, а каждая ячейка экономит
4 байта.

## Следствия

- Пустые строки не занимают памяти вообще: лист с данными в строках 1 и 1 000 000
  хранит два элемента в `row_ids`.
- Поиск ячейки — `O(log rows + log cols)`, обход строки — непрерывный срез.
- Ячейки обязаны поступать в порядке возрастания. Это гарантирует
  `WorksheetBuilder::push`, а не сортировка: потоковый парсер `sheet*.xml` и так
  читает строки по порядку, а молчаливая сортировка скрыла бы баг в парсере.
- `Worksheet` неизменяем после сборки. Для редактирования (не входит в скоуп
  проекта — `ROADMAP.md` §2) понадобится отдельный тип или перестроение.
- 32-битные смещения ограничивают лист ~4.29 млрд ячеек; `WorksheetBuilder`
  возвращает ошибку при исчерпании, а не переполняет индекс.

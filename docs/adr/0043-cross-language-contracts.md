# ADR-0043: Контракты кадра и SAB — валидация `DisplayList` и единый источник раскладки кольца

**Статус:** Предложено
**Дата:** 23.10.2026
**Контекст:** аудит архитектуры v1.4.3
(`docs/analysis/architecture-audit-2026-10-23.md`, §3.3); бинарный контракт
кадра `DLST`/`DL_VERSION = 4`; SAB-кольцо транспорта (ADR-0021)
**Связанные ADR:** [ADR-0003](0003-render-boundary.md) (граница `render`),
[ADR-0021](0021-frame-transports.md) (SAB и bytes),
[ADR-0028](0028-typed-wire-protocol.md) (Rust как источник истины для wire),
[ADR-0029](0029-main-thread-render-backend.md) (painter на main)

---

## Контекст

- `DisplayList` — проводной формат кадра между сборщиком (форматным крейтом)
  и painter'ом. TS тело кадра не разбирает: painter читает его прямо из SAB
  или из переданного буфера. Поэтому формат обязан быть самодостаточным и
  проверяемым на стороне Rust.
- Размеры payload'ов записаны трижды: в doc-комментарии
  (`crates/render/src/display_list.rs:3-7`), в писателе (`:283, 330, 364`) и
  в читателе (`:552, 586, 628`). `push_tag` принимает `_payload_len` и
  игнорирует его (`:443-449`), то есть выравнивание держится соглашением, а
  не проверкой. Ошибка вызывающего даёт кадр, который читатель разберёт
  неверно.
- `DisplayList::from_bytes` использует `bytemuck::from_bytes`
  (`display_list.rs:423`), который паникует на невыровненном срезе. В
  продакшене painter вызывает его с произвольным `&[u8]`
  (`painter/painter_2d.rs:81`).
- Раскладка SAB-кольца описана независимо: Rust
  (`crates/render/src/sab/ring.rs:3-12`) и TS
  (`packages/core/src/sab/protocol.ts:2-4`). Константы совпадают, но
  семантика уже разошлась: Rust считает `u32` с `wrapping_sub`
  (`ring.rs:24-31`), TS — знаковые `number` без wrap (`protocol.ts:20-26`).
  Кросс-теста нет: `packages/core/test/frame_transport.spec.ts` проверяет
  TS сам себя, тесты `ring.rs` — Rust сам себя. Смена `HEADER_BYTES` или
  порядка полей не будет поймана ничем.

## Решение

1. **Одна таблица команд.** В `crates/render/src/display_list.rs` заводится
   единственная таблица `tag → (имя, размер payload)`, общая для писателя и
   читателя. Добавление команды без записи в таблицу не компилируется или
   падает на `debug_assert` в тестах.
2. **`DisplayList::validate`.** Функция проверяет магию, версию, заголовок,
   `cmd_count`, границы `strings_off`, размер каждой команды и корректность
   ссылок `StringRef`. Вызывается в отладочных сборках и в тестах; painter
   получает ошибку `DecodeError` вместо паники или тихого мусора.
3. **Безопасное чтение заголовка.** `from_bytes` использует
   `pod_read_unaligned`/`try_from_bytes`; паника на выравнивании исключена.
4. **SAB: Rust — источник истины.** `HEADER_BYTES` и `SLOT_COUNT` либо
   экспортируются из wasm (`sab_header_bytes()`, `sab_slot_count()`), либо
   генерируются в TS тем же генератором, что `wire.ts` (ADR-0028). Ручная
   копия констант удаляется.
5. **Кросс-языковой тест.** `wasm-bindgen-test` собирает кольцо на Rust,
   пишет кадр, читает заголовок и полезную нагрузку через TS-хелперы
   (и наоборот, если появится TS-писатель). Тест входит в CI.
6. **Арифметика TS — модульная.** `hasFreeSlot`/`canRead`/`writerSlot`
   приводят значения к `>>> 0`; сравнения и разности выполняются в
   беззнаковой арифметике, как в Rust.
7. **`DL_VERSION` не меняется.** Формат остаётся версией 4; любое изменение
   набора команд или их payload — новое значение версии и отдельный ADR.

## Рассмотренные варианты

- **Оставить ручное дублирование.** Отклонено: оно уже разошлось по
  семантике, а цена ошибки — порча кадра или зависший экран в SAB-режиме.
- **Схема (protobuf/flatbuffers) для DisplayList.** Отклонено: бинарный
  формат сознательно компактный, painter читает его без распаковки; схема
  добавила бы зависимости и слой кодогенерации.
- **Генерировать TS-читатель тела кадра.** Не требуется: TS тело не читает,
  достаточно констант заголовка и теста на совместимость.
- **Отказаться от SAB-констант в TS, оставить только Rust.** Нельзя:
  TS-хелперы нужны отладочному reader'у и тестам транспорта.

## Последствия

- Добавление команды требует правки одной таблицы и повышения
  `DL_VERSION`; забыть размер больше нельзя.
- `validate` даёт диагностируемую ошибку вместо паники `bytemuck`; цена —
  один проход по командам в отладочных сборках.
- Смена раскладки SAB ломает кросс-тест, а не продакшен.
- Публичный API `render` расширяется `validate` и, возможно,
  `DecodeError`; существующие сигнатуры не меняются.
- Формат кадра и производительность painter'а не меняются: проверка
  выполняется только в тестах/отладке.

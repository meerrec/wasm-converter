# Программа «Строгий собственный просмотр DOCX/XLSX»

**Статус:** принята 21.11.2026; этап 1 заведён эпиком [#71](https://github.com/meerrec/wasm-converter/issues/71).

**Цель:** довести существующий Rust/WASM-вьюер до строгого соответствия на явно сертифицированной матрице возможностей DOCX/XLSX. Эталон визуальной сверки — заранее сохранённые снимки Office Online.

## Принятые ограничения

- Вьюер только собственный: `crates/docx`, `crates/xlsx`, `crates/render`, существующие WASM-модули и `packages/core`.
- Office Online Server, WOPI, Office iframe, desktop Office, LibreOffice-WASM, ONLYOFFICE и другие внешние движки просмотра не входят ни в продукт, ни в тестовый runtime.
- Office Online используется только при подготовке эталонных PNG и manifest. Продукт и CI работают автономно, без обращений к Office.
- Strict OOXML и строгое визуальное соответствие — разные требования. Эта программа относится к тексту, геометрии, объектам, пагинации и рисованию.
- Обещание строгого соответствия относится к сертифицированной матрице. Неподдерживаемая возможность должна давать явный `unsupported-visible`, а не исчезать молча.
- Средний SSIM не доказывает соответствие: проверяются все выбранные страницы/экраны, текст, число страниц и присутствие объектов.

## Целевой контур

```text
Продукт:
DOCX/XLSX → собственный parser → model → layout → Layout IR
          → WASM/canvas + PDF + TextLayer/hit testing

Подготовка тестов:
фикстура → Office Online → reference PNG + manifest.json
фикстура → наш вьюер    → actual PNG
reference + actual     → автономный diff → JSON + HTML report
```

После формирования эталонов разработка и CI не требуют Office. Обновление baseline — отдельная явная операция и ревью, а не побочный эффект обычного теста.

## Этап 1: автономный визуальный оракул и базовая линия (2–3 недели)

1. **Эталонный корпус** — [#75](https://github.com/meerrec/wasm-converter/issues/75): 20 DOCX и 20 XLSX; PNG без JPEG-сжатия, SHA-256 входного файла, `manifest.json` с браузером, ОС, viewport, DPR, zoom, режимом, страницей DOCX либо листом/печатной страницей/видимым диапазоном XLSX.
2. **Захват собственного вьюера** — [#72](https://github.com/meerrec/wasm-converter/issues/72): Playwright открывает существующий `examples/viewer`, восстанавливает состояние manifest, ждёт готовности без длинных sleep и сохраняет actual PNG либо структурированную ошибку.
3. **Автономное сравнение** — [#77](https://github.com/meerrec/wasm-converter/issues/77): размеры, pixel diff, постраничный SSIM, число страниц/листов, маски только для документированных динамических областей, `report.json` и `report.html` с reference/actual/diff.
4. **Базовая классификация** — [#78](https://github.com/meerrec/wasm-converter/issues/78): разнести расхождения по `parse`, `model`, `layout`, `font`, `render`, `harness`, `reference`; выделить молчаливо пропущенные XML-конструкции и минимальные фикстуры.
5. **Первые регрессии** — [#74](https://github.com/meerrec/wasm-converter/issues/74) DOCX `long_table`, [#73](https://github.com/meerrec/wasm-converter/issues/73) DOCX `long_table_header_repeat`, [#76](https://github.com/meerrec/wasm-converter/issues/76) XLSX `print_extent` для изображений, диаграмм и переполнения текста.

**DoD этапа 1:** одна локальная команда воспроизводит capture и сравнение без сети; отчёт содержит все выбранные страницы/экраны и отличает визуальное расхождение от сломанного харнесса; базовая линия привязана к ревизии; три стартовых дефекта имеют регрессионные проверки.

## Этап 2: детерминированный текст и раскладка (6–10 недель)

- Один конвейер Unicode → bidi → script itemization → shaping → kerning/ligatures → advances → line breaking → positioned glyphs для измерения, canvas, PDF и TextLayer.
- Перейти от повторного shaping строки браузером к позиционированным glyph runs в DisplayList.
- Версионировать шрифтовые ассеты, resolver семейств/начертаний и fallback; в сертифицированном режиме запретить незаявленную подстановку.
- Сохранить границы ADR-0003/0007/0025: форматная раскладка остаётся в `docx`/`xlsx`, общие текстовые и графические примитивы — в `render`; новый внешний backend и отдельный XLSX-layout crate не вводятся.
- Если canvas-вывод мешает кросс-браузерной детерминированности, добавить собственный software rasterizer в `render`, используя canvas только для вывода готового RGBA-кадра.

**DoD:** одинаковые Layout IR и TextLayer на всех путях; зафиксированная среда даёт стабильные кадры; Chrome/Firefox/Safari проходят согласованные golden-тесты при одинаковых DPR и zoom.

## Этап 3: DOCX (12–20 недель для приоритетной матрицы)

1. Поток и пагинация: переносы, widow/orphan, keep-next/keep-lines, секции, колонки, разрывы, колонтитулы, поля, docGrid.
2. Таблицы: AutoFit/fixed, merged/nested, длинные таблицы, повтор заголовков, `cantSplit`, строки выше страницы, границы и поля ячеек.
3. Объекты: inline/floating, все виды обтекания, anchors, relative positioning, z-order, текстовые блоки, группы, transforms, DrawingML, VML, `AlternateContent`.
4. Содержимое: сноски/концевые сноски, комментарии, ревизии, Office Math, поля/TOC/перекрёстные ссылки; SmartArt и OLE — отдельные решения о поддержке.

**Гейт:** точное число страниц на сертифицированном корпусе, все страницы в отчёте, unit-тесты геометрии плюс визуальные регрессии; допуск ±1 страница не применяется.

## Этап 4: XLSX (16–24 недели без полного formula engine)

1. Геометрия: ширины столбцов, автоматические высоты строк, wrap/overflow, rich text, merged/hidden, freeze panes, прокрутка и zoom.
2. Форматирование: числовые форматы, даты 1900/1904, локали, темы/стили, условное форматирование, data bars/icon sets/color scales.
3. Объекты: images/cropping, shapes, комбинированные диаграммы, оси/легенды/labels, comments/notes, pivot/slicers/controls по матрице.
4. Печать: `print_extent`, print areas, ручные разрывы, repeating titles, fit-to-page, headers/footers, page order, несколько листов.
5. Формулы: read-only сертификация cached values допустима только с распознаванием устаревшего кэша. Полный пересчёт после редактирования требует собственного formula engine: AST, dependency graph, incremental recalculation, функции, references, arrays, circulars и external-link state; это отдельная программа работ.

## Этап 5: сертификация и regression-гейты (6–8 недель после закрытия матрицы)

Каждый дефект проходит цикл: Office Online diff → минимальная фикстура → диагностика слоя → исправление → unit test → native golden → WASM golden → полный corpus.

**DoD сертифицированного просмотра:**

- 100 % документов матрицы открываются без молчаливой потери содержимого;
- точное число страниц DOCX и правильные листы/области печати XLSX;
- полное текстовое содержимое и присутствие всех поддерживаемых объектов;
- каждая страница/экран проходит согласованный визуальный порог;
- нет незаявленных шрифтовых подстановок;
- canvas, PDF и TextLayer используют одну геометрию;
- Chrome, Firefox и Safari дают детерминированный кадр в зафиксированных условиях;
- ограничения явно видны пользователю и попадают в отчёт совместимости.

## Ориентировочные сроки и граница обещания

Команда 4–6 инженеров: детерминированная основа и оракул — 2–3 месяца; первая сертифицированная DOCX-матрица — 5–8 месяцев; XLSX — 8–12 месяцев; широкая совместимость — 12–24 месяца. Полный собственный formula engine Excel оценивается отдельно. Произвольные файлы Word/Excel требуют постоянного расширения матрицы; конечная точка «любой документ гарантированно совпадает» самостоятельному рендереру не обещается.

# Спринт 11: SAB + CLI, закрытие долгов DOCX

Отчёт о ходе работы. Ветка `main`, 12.10.2026. Числа получены прогонами
этого захода, если не сказано иное. Заход шёл волнами параллельных
субагентов; 30+ коммитов от точки `d2b3a01`.

## Что сделано

**Оба транспорта кадра — first-class** (`ae36da2`, `433f353`, ADR-0021).
Путь без SAB перестал быть аварийным: `ArrayBuffer` с возвратом буфера
transfer'ом, двойная буферизация в обоих путях, один и тот же кадр и painter,
выбор автоматический (`crossOriginIsolated`) с явной опцией
`transport: 'sab' | 'bytes' | 'auto'`; явный `sab` без заголовков — ошибка
инициализации, а не тихая подмена. README документирует COOP/COEP и что даёт
SAB. `packages/core` — 84 теста, включая `frame_transport.spec.ts`.

**CLI** (`c8a2ca2`, `@doc-converter/cli`): `convert <input> -o <out>`
(DOCX → pdf/md/html/txt, XLSX → pdf), `batch <файлы|каталоги|glob> --out <dir>
--workers N` с прогрессом, рекурсивным обходом и проверкой коллизий имён;
`WorkerPool` на `node:worker_threads` — воркер грузит wasm один раз, упавший
воркер заменяется. 41 тест; `batch` по `test-fixtures/xlsx` — **116 файлов за
0,20 с на 4 воркерах** (DoD «100 файлов < 30 с» перекрыт). Wasm-модули
`--target web` грузятся в Node байтами через `init({module_or_path})` — сборка
под nodejs не понадобилась.

**Таблицы — главный приоритет захода.**
- *Раскладка* (`f851fce`, `dee1941`, `dfc8c7f`): таблица кладётся
  постраничными фрагментами; строка разрывается на границе страницы (как
  «разрешить перенос строки» в Word), `w:cantSplit` переносит строку целиком,
  `w:tblHeader` повторяет заголовок на каждой странице-продолжении, строка выше
  страницы разрезается принудительно, `w:vAlign`, вложенные таблицы
  раскладываются рекурсивно, поля `w:tcMar`/`w:tblCellMar` учитываются.
  Ширины: `w:tblW`/`w:tblGrid`/`w:tcW`, при переполнении — пропорциональное
  сжатие до полосы (отклонение от Word, который допускает выход за поле, —
  записано в доккомментарии; пользователь требовал «умещать таблицу на
  странице»). Дефект `w:tblGrid` (818,13 px при границе 718,13) закрыт.
- *Canvas* (`7f0b188`): границы рёбер со схлопыванием по весу (double > thick >
  single > dashed > dotted), стили single/double/dashed/dotted, цвет, заливка
  `w:shd` (включая `val="clear"` с `w:fill` — так Word пишет заливку ячейки),
  `vMerge`-продолжение без содержимого. Формат DisplayList не менялся.
- *PDF* (`f563339`): те же границы/заливка/vAlign/вложенность; неправота двух
  тестов доказана (постраничная сверка и покрытие контура), а не подогнана.
- *Стиль таблицы* (`c0f85f5`): `w:tblStyle` резолвится через `w:basedOn`,
  условные форматы `w:tblStylePr` по флагам `w:tblLook` (firstRow/lastRow,
  firstCol/lastCol, полосы, угловые ячейки); прямые `w:tblBorders`/`w:tcBorders`
  и заливка ячейки приоритетнее стиля; неизвестный стиль игнорируется.
- *Экспорт* (`36e0205`): `rowspan` из `vMerge` (с учётом `gridSpan`), границы и
  заливка инлайновыми стилями, `padding` из полей ячейки, `colgroup` из
  `w:tblGrid`, выравнивание; в Markdown — экранирование `|` и строка
  разделителей GFM по `w:jc`.
- *Фикстуры и бенчмарк* (`0bdc018`, `205d82a`): 7 новых фикстур (длинная
  таблица, повтор заголовка, `cantSplit`, строка выше страницы, шире полосы,
  поля+vAlign, 100-страничная на 4800 строк), сайдкары, criterion-бенчмарк
  пагинации. Дифференциальный гейт против mammoth: 83 кандидата, **81/81
  match** (`dd21fd1`).

**Текст и шрифты** (`463d54c`). `w:rFonts` доезжает до измерения и до кадра —
переносы считаются тем же лицом, которым строка рисуется. Прогоны одного
абзаца складываются в одну строку: `basic/multiple_runs.docx` даёт 1 строку
вместо 4, `many_runs_paragraph` — 7 строк вместо «по строке на прогон».

**Рисунки** (`6dc8ff8`, `c8893c8`, `5ada811`). `Document` несёт байты
медиачастей, на которые ссылаются рисунки; раскладка отдаёт
`LayoutItem::Image` с реальными размерами из `extent`; canvas и PDF рисуют
изображения (плейсхолдер остаётся только там, где байтов нет); вьюер получает
`docx_images()`/`docx_image_bytes(id)` и регистрирует `ImageBitmap` до первого
кадра. E2E в реальном Chromium подтверждает цепочку до пикселей.

**Колонтитулы** (`bf0d123`, `14a90b4`, `954b23a`, `42b02e0`). `PageLayout`
получил `chrome: Vec<PageChrome>` рядом со страницами (`Page` не менялся —
потребители не сломались); выбор по `w:titlePg` и `w:evenAndOddHeaders` с
откатом к обычному; в PDF рисуются после тела тем же диспетчером, шрифты
колонтитулов собираются заранее. Поля `PAGE`/`NUMPAGES` разворачиваются
(двухпроходная раскладка для `NUMPAGES`), кэшированный результат Word
игнорируется; цена — 20,7 мс без полей против 39,8 мс с `NUMPAGES` на
100-страничной фикстуре при бюджете 500 мс.

**Многоколоночность** (`1cecadb`) — последний маркер `TODO (Спринт 10)` снят.
`w:cols` с равными и неравными ширинами, `w:br type="column"`, переполнение
колонки перетекает в соседнюю, новая страница начинается с первой колонки.

**Точность пагинации** (`aba3fae`). Интервалы `space_before`/`space_after`
отбрасываются на границе страницы, как в Word; первая страница документа
намеренно исключение (закреплено эталонным тестом фикстуры).

**Оракул DOCX** (`1d6ba66`, `cd85e50`): `scripts/oracle-docx-pages.sh` —
число страниц и постраничный SSIM против LibreOffice, внешними `soffice`/
`pdftoppm`/`ffmpeg`; шаг в `.github/workflows/oracle.yml`; методика —
`docs/testing/docx-oracle.md`. Числа прогона — раздел «Метрики».

**Бенчмарки против JS** (`efe5dfe`): `pnpm bench:js`, отчёт `docs/bench-js.md`.

## Метрики

- **Тесты.** Rust: `cargo test --workspace` — все цели зелёные (`docx` 404
  lib + интеграционные, `pdf` 19 сюит 214 тестов, `render` 68+4). JS:
  `core` 84, `cli` 41. Сквозные: viewer-xlsx 40/40, viewer-docx 31 passed
  (2 skip — корпус только в chromium).
- **Гейты.** `cargo fmt --all --check`, `cargo clippy --workspace --all-targets
  -- -D warnings`, `cargo deny check` — чисто. `pnpm size-limit`: просмотрщик
  **287,31 КБ** (бюджет 300), модуль DOCX **380,62 КБ** (бюджет поднят
  380 → 400 КБ, `e4ef94f`, причина — пришедшие фичи).
- **DoD спринта 9 (сверка с эталоном LibreOffice 26.8.1.1), прогон 12.10.2026.**
  DOCX, 98 фикстур вне `broken/`: **число страниц ±1 — 97 из 98 (99,0 %)**
  (единственное расхождение — `tables/table_100_pages.docx`: у эталона 150
  страниц, у нас 100); **SSIM первой страницы: min 0,5533, mean 0,9782,
  ≥ 0,95 у 92 из 98 (93,9 %)**. Ниже порога шесть фикстур, пять из них —
  табличные (`long_table` 0,5533, `long_table_header_repeat` 0,5880,
  `table_100_pages` 0,7793, `cant_split_rows` 0,8259, `row_taller_than_page`
  0,8369) и `basic/many_runs_paragraph` 0,9443. Разрез: таблицы (16 фикстур)
  mean **0,8949**, всё остальное (82 фикстуры) min **0,9443**, mean **0,9945**.
  Раскладка 100 страниц — max **20,10 мс** (DoD «пагинация 100 страниц < 500 мс»
  закрыт). Ещё 1 фикстура из `broken/` сравнима (`missing_style_and_abstract_num`
  0,9932); 5 не сравнимы: 4 не открыл эталон, 1 отверг наш экспорт
  (`macro_enabled` — `.docm` вне области).
  XLSX, 12 фикстур умолчания: **SSIM первой страницы min 0,6128, mean 0,9461,
  ≥ 0,95 у 10 из 12** — средняя по умолчанию DoD v1.0 «SSIM ≥ 0,95» **не
  выполняется**. По 104 однолистовым: min 0,5170, mean 0,9573, ≥ 0,95 у 89
  (85,6 %); число страниц не совпало у 4. Причина худших найдена и измерена:
  у XLSX-экспорта систематический горизонтальный сдвиг начала листа
  относительно эталона (ink-box `+93` против `+107` у эталона, на плотных
  сетках — до 19 px), на DOCX-пути сдвига нет; адрес отдельного слайса —
  origin/ширина левого гуттера в XLSX-экспорте. Отчёты:
  `oracle-out-docx/report.md`, `oracle-out/report.md`.
- **DoD Спринта 11.** CLI: 100 файлов < 30 с — перекрыт (116 за 0,20 с).
  Оба пути кадра — работают, тесты обоих есть. «Отчёт ×10–300 vs JS-аналоги»
  — **не подтверждён**: на эквивалентной паре DOCX→HTML против mammoth
  медиана **×5,3** (разброс ×3,7–6,8; холодный старт 105 мс против 1151 мс).
  Всё, что давало ×10+, — сравнение нашего процесса с нашим же подпроцессом
  или файлы, где mammoth вклеивает картинки в base64, а мы отдаём `<img>` без
  данных; по XLSX мы в 2–10 раз медленнее exceljs/SheetJS, потому что делаем
  строго больше (разбор + раскладка + отрисовка + PDF). Пары не подгонялись:
  скрипт помечает несопоставимые строки и не пускает их в сводку.

## Отклонения от плана и спорные решения

1. **Эталон — LibreOffice, а не MS Word** (унаследовано от Спринта 9).
   Word в CI нет; для DOCX это та же замена, что уже принята для XLSX.
2. **Бенчмарк-цель ×10–300 не достигнута и пересмотрена** (см. «Метрики»).
   Роадмап задним числом не переписываем — отклонение фиксируется здесь.
   Конвенция изменена 15.10.2026: ROADMAP.md ведётся как живой документ и
   правится по факту — см. «Соглашения» в CLAUDE.md.
3. **Бюджет DOCX-модуля поднят 380 → 400 КБ.** Рост запланированный
   (комментарий `.size-limit.mjs` предсказывал его в Спринте 10); факт
   зафиксирован в `ROADMAP.md` §9.
4. **Ширина таблицы клампится до полосы набора**, тогда как Word допускает
   выход за поле. Требование пользователя — «умещать таблицу на странице».
5. **`vMerge` через разрыв страницы** продолжается пустой ячейкой той же
   высоты; содержимое не дублируется.
6. **Строка выше страницы** разрезается принудительно — иначе она не
   помещается ни на одной странице.
7. **Медиачасть живёт в `Document`** (байты только тех частей, на которые
   ссылаются рисунки) — компромисс память/доступ; `Archive` по-прежнему не
   удерживается.
8. **Колонтитулы — `PageChrome` рядом со страницами**, а не поля `Page`:
   `Page::items` — поток содержимого, по нему режется таблица; `chrome`
   рисуется отдельным слоем.
9. **SheetJS 0.18.5 в devDependencies** (только бенчмарк) имеет открытые
   CVE-2023-30533 и CVE-2024-22363 — в npm пропатченных версий нет. Пара
   снимается одной строкой в `scripts/bench-js.mjs`, если это неприемлемо.

## Что осталось незакрытым

- **XLSX: горизонтальный сдвиг начала листа** — найден оракулом, локализован
  и **починен** (`ee4fd76`: лист получил паддинг в 1 pt, совпадающий с
  эталоном). Замер после починки: `size-200x10x1` 0,5170 → **0,7858**,
  `content-dense` 0,5684 → **0,8084**, `scale-ten-pages` 0,6128 → **0,8406**,
  `values-strings` 0,9930 → **0,9996** (min SSIM по страницам, тот же оракул).
  Полный прогон по 104 книгам после починки не повторялся — числа выше по
  четырём худшим; средняя по корпусу должна подрасти, но точное новое
  значение не измерено.
- **Сноски и комментарии**: разбор в модели есть, раскладка их не использует.
- **Обтекание текстом вокруг плавающих рисунков** — не сделано (долг
  Спринта 9), рисунок вынимается из потока.
- **VML-фолбэки**: `alternate_content/fallback_only.docx` остаётся пустым
  листом (единственная фикстура в `DRAWINGS_NOT_PAINTED`).
- **Поля `PAGE`/`NUMPAGES`** не разворачиваются в ячейках таблиц и внутри
  гиперссылок; `w:pgNumType/@start` в модели нет — нумерация физическая.
- **`hyphenation.rs`** не создан (в роадмапе опционален).
- **`w:sep`** (разделительная линия колонок) не рисуется.
- **`compress`** не проброшен в CLI: `PdfOptionsJs` не несёт поля (сжатие в
  крейте включено по умолчанию).
- **Остаточный флейк корпусного замера**: `waitForFrame` может поймать окно
  между resize и перерисовкой (1 прогон из 5 до правки; после — 6/6 зелёных).
  Правка протокола ожидания — отдельное решение.

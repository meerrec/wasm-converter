# Спринт 6 — блокеры

Обновлено: 2026-10-06 · ветка `sprint/6-basic-pdf`. Блокеров: 1 (B-1 решён).

## B-1. Размер WASM-бандла вырос в 6,1× после подключения PDF-экспорта

**Суть.** После того как `crates/wasm` стал линковать `doc-converter-pdf`
(→ `printpdf` 0.8.2), поставочный `doc_converter_wasm_bg.wasm` вырос
с 649 343 Б до 3 988 393 Б raw (6,14×), в gzip — 1 671 170 Б. Бюджет
ROADMAP §9 «Worker bundle — 600 КБ (gzip)» превышен в 2,8×; относительно
зафиксированного там же факта «168 КБ wasm» рост ~10×. Гейт «регрессия
> 10% блокирует merge» этого не видит: `.size-limit.json` покрывает
только JS (`packages/core/dist/*.js`), строки на wasm нет, а сам вызов
в CI мягкий (`pnpm size-limit || true`). Функционально всё работает:
экспорт PDF из UI идёт end-to-end, e2e зелёные в chromium/firefox/webkit
(коммиты 7ab7a2d, c5b7402, f79e788, 409d47f; `examples/viewer-xlsx/e2e/pdf.spec.ts`).

**Доказательства.**

- Текущий замер (2026-10-06, локальная `pnpm build:wasm`):
  - `ls -la packages/wasm/pkg/*.wasm` → 3 988 393 Б;
  - `gzip -c packages/wasm/pkg/doc_converter_wasm_bg.wasm | wc -c` → 1 671 170;
  - `brotli -c -q 11 … | wc -c` → 1 276 070;
  - рост по raw: 3 988 393 / 649 343 = 6,14×.
- Базовая линия 649 343 Б — сборка до подключения PDF-символов,
  зафиксирована в `docs/analysis/pdf-lib-spike.md:57` и
  `docs/sprint-6/plan.md:23`. `packages/wasm/pkg/` в `.gitignore`, прежний
  артефакт не сохранён, поэтому это документированный замер, а не
  переизмеренный здесь.
- Бюджет: `ROADMAP.md:899–912` (§9 «Бюджеты размера (gzip)»): строка 907 —
  «Worker bundle | 600 КБ | 600 КБ | 4,7 КБ JS + 168 КБ wasm»; строки
  909–910 — «size-limit меряет только JS: wasm приезжает отдельным ассетом
  и в бюджет воркера входит отдельной строкой»; строка 912 — «CI-гейт:
  регрессия > 10% блокирует merge».
- Гейт не работает даже для JS: `.github/workflows/ci.yml:109` —
  `pnpm size-limit || true`.
- Причина — неопциональные зависимости `printpdf` 0.8.2 (проверено в
  `~/.cargo/registry/src/*/printpdf-0.8.2/Cargo.toml`; ни у одной нет
  `optional = true`):
  - `[dependencies.svg2pdf] version = "0.13.0"` (стр. 207–208);
  - `[dependencies.allsorts-subset-browser] version = "0.16"` (стр. 142–145);
  - `[dependencies.lopdf] version = "0.35.0"` (стр. 184–187).
  `cargo tree -p doc-converter-wasm -i usvg -i rustybuzz -i fontdb -i svg2pdf`
  подтверждает пути: `svg2pdf → usvg 0.45.1 → rustybuzz/fontdb`, плюс
  `usvg ← resvg ← svg2pdf`; в `Cargo.lock` — `svg2pdf`, `usvg`, `rustybuzz`,
  `fontdb`, `allsorts-subset-browser`, `lopdf`.
- Фичами не отключить: `default-features = false` уже стоит
  (`Cargo.toml:47`, workspace); включение default-фичи `html` тянет
  MPL-2.0 (resvg) и не проходит allow-list `deny.toml:8`.
- Ориентир по вкладу: три новых начертания Carlito дают ~289 КБ
  (`docs/analysis/pdf-lib-spike.md:60–62`), остальной рост — код и данные
  стека `printpdf`.
- Дополнительный резерв: `wasm-opt` (Binaryen) не установлен — `command -v
  wasm-opt` пуст, в CI его тоже нет; `scripts/build-wasm.sh:19–22` применяет
  его, только «если есть в PATH». То есть 3,99 МБ — размер без
  post-обработки `wasm-opt` сверх `cargo --release`
  (`[profile.release]`: `lto = "fat"`, `codegen-units = 1`,
  `opt-level = "s"`, `panic = "abort"`, `strip = "symbols"`).

**Варианты решения** (рекомендация не даётся — решение за архитектором):

1. **Принять в спринте 6 и загейтить.** Зафиксировать факт в ROADMAP §9
   (переписать строку факта), добавить бюджет на `packages/wasm/pkg/*.wasm`
   в `.size-limit.json` (базовая линия — текущий размер) и `binaryen`/
   `wasm-opt` в CI; ленивую загрузку PDF-модуля вынести отдельной задачей
   в бэклог/Спринт 7.
   - Плюсы: DoD спринта 6 размером не ограничен — срок не сдвигается;
     регрессия перестаёт быть невидимой; `wasm-opt` даёт запас поверх
     текущего размера без изменения архитектуры.
   - Минусы: 1,67 МБ gzip на старте просмотрщика остаются до отдельной
     задачи; перенос линии бюджета на текущий размер узаконивает
     превышение §9.
2. **Ленивая загрузка сейчас.** Вынести PDF-экспорт во второй
   wasm-модуль (`wasm-pack` по отдельному крейту, например
   `crates/pdf-wasm`), подгружаемый воркером по клику «Экспорт в PDF».
   - Плюсы: просмотрщик стартует с прежним лёгким модулем; бюджет §9
     для базового пути соблюдён.
   - Минусы: второй билд и артефакт в CI; API динамической загрузки
     и её ошибок в воркере; задержка на первый экспорт; заметная работа —
     вероятно, не влезает в остаток спринта 6.
3. **Только принять.** Зафиксировать факт в отчёте эпика, ничего в CI
   не менять.
   - Плюсы: минимум работы.
   - Минусы: регрессия останется невидимой для гейта, нарушение §9 не
     будет отслеживаться.

**Статус:** решён 06.10.2026: вариант 2 (ленивая загрузка).

**Результат.** PDF-экспорт вынесен в отдельный wasm-модуль: крейт
`crates/pdf-wasm` → `packages/wasm-pdf/pkg`, воркер грузит его динамическим
`import()` по клику «Экспорт в PDF» (`packages/core/src/worker/worker.ts:63`,
`:316–317`). Основной модуль вернулся к базовой линии: 649 522 Б raw (было
3 988 393 Б), 275 521 Б gzip (-9) — в бюджете 300 КБ gzip, добавленном в
`.size-limit.mjs`. PDF-модуль — 4 166 980 Б raw / 1 756 515 Б gzip; своего
бюджета не имеет, платится по требованию. Ленивость доказана e2e-тестом
`examples/viewer-xlsx/e2e/lazy-pdf.spec.ts`: до клика — ни одного запроса
модуля, после — ровно один, повторный экспорт идёт из собранного инстанса.
Коммиты: 12c1f73, eb5ffce, 6d0f5ea, 01e9edb, d5a0845.

## К сведению (не блокеры)

- **(а) Экспорт PDF синхронный в воркере.** `export_pdf`
  (`crates/pdf-wasm/src/lib.rs:125`) — синхронная `#[wasm_bindgen]`
  функция, воркер зовёт её прямо в обработчике сообщения
  (`packages/core/src/worker/worker.ts:316–317`), после ленивой загрузки
  модуля. На большой книге кадровый
  цикл встанет на время сборки; прогресса, кроме disabled-кнопки, нет.
  Потоковая запись отсутствует и на стороне printpdf (документ копится
  в памяти) — это решение 2 плана спринта, ADR-0008.
- **(б) Отсутствующие глифы.** Нет CJK, эмодзи и части редких латинских
  (например U+0108) — такие символы дают пустой глиф; fallback-шрифт
  отложен в бэклог (`docs/adr/0009-font-subsetting.md:69–70`).

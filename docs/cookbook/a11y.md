# Рецепты: доступность DOCX

Обычный просмотрщик рисует документ на canvas: текст виден, но недоступен
скринридеру, выделению и копированию. Флаг `a11y: true` включает прозрачный
DOM-слой поверх canvas — TextLayer. Слой не меняет кадр и не пересчитывает
геометрию: координаты приходят из той же раскладки, что уходит в canvas.

---

### <a id="a11y-01"></a>Рецепт 1. Включить доступный режим

**Задача.** Сделать документ читаемым скринридером, выделяемым мышью и
копируемым — без изменения картинки.

```ts
import { createDocxViewer } from '@meerrec/core';

const viewer = await createDocxViewer(document.getElementById('viewer')!, {
  workerUrl,
  docxWasm,
  a11y: true, // по умолчанию выключено
});

await viewer.open(bytes);
```

После открытия в разметке появляются:

- `.dc-text-layer` с `role="document"` и `tabindex="0"` — корень слоя поверх
  canvas;
- `.dc-text-semantic` — семантическое дерево `paragraph`, `heading` (с
  `aria-level`), `table`, `row`, `cell`/`columnheader` (с
  `aria-rowindex`, `aria-colindex`, `aria-rowspan`, `aria-colspan`);
- `.dc-text-visual` с `aria-hidden="true"` — виртуализированные построчные
  spans для нативного выделения.

Canvas получает `aria-hidden="true"`; `user-select: none` стоит только на
семантическом дереве, поэтому выделяется визуальный слой.

**Под капотом.** TextLayer — второй выход раскладки, а не часть `DisplayList`:
`runs` с `bbox`/`lineRect` приходят из Rust, DOM-порядок логический, а строку
шейпит браузер ([ADR-0041](../adr/0041-text-layer-dom-overlay.md)). Поэтому
включение слоя не меняет ни одного пикселя кадра — это проверяет e2e
`pixel_diff`. Для RTL `readingOrder` тоже логический, визуальный порядок даёт
браузер; canvas получает RLM (U+200F) и правое выравнивание, а `w:bidiVisual`
зеркалит только колонки, не меняя логический `col`.

### <a id="a11y-02"></a>Рецепт 2. Программно получить TextLayer

**Задача.** Построить оглавление, поиск или собственный экспорт по тем же
данным, что видит DOM-слой.

```ts
import type { TextLayer, TextRun } from '@meerrec/core';

// Весь документ: runs в логическом порядке + срезы по страницам.
const full: TextLayer = await viewer.getFullTextLayer();

const headings: TextRun[] = full.runs.filter((run) => run.headingLevel !== null);
for (const run of headings) {
  console.log(`${run.headingLevel}: ${run.text}`);
}

for (const slice of full.pageMap) {
  const runs = full.runs.slice(slice.start, slice.start + slice.count);
  console.log(`страница ${slice.page}: ${runs.length} runs`);
}

// Одна страница (0-based): pageMap содержит один срез, readingOrder остаётся
// сквозным по документу.
const first: TextLayer = await viewer.getTextLayer(0);
```

Поля `TextRun`, на которые опираются такие сценарии:

- текст и геометрия — `text`, `bbox`, `lineRect` (пиксели раскладки);
- положение — `page`, `lineIndex`, `fragmentIndex`, `readingOrder`;
- направление — `direction`, `bidiLevel`, `textAlign`;
- структура — `nodeId`, `blockKind`, `headingLevel`, `table`
  (`tableId`, `row`, `col`, `colSpan`, `rowSpan`, `isHeader`);
- оформление — `style` (`fontFamily`, `sizePx`, `bold`, `italic`,
  `underline`, `color`).

**Под капотом.** `getTextLayer`/`getFullTextLayer` — данные, а не DOM, и
работают даже при `a11y: false`. `pageMap` — не копия страниц, а диапазоны
`start`/`count` в общем массиве `runs`, поэтому страницы не дублируют текст
в памяти.

### <a id="a11y-03"></a>Рецепт 3. Почему по умолчанию выключено

**Задача.** Решить, когда включать флаг и как менять его в приложении.

```ts
// Флаг читается один раз — при создании вьюера.
const viewer = await createDocxViewer(host, {
  workerUrl,
  docxWasm,
  a11y: userSettings.a11y,
});

// На лету флаг не переключается: чтобы изменить режим, пересоздайте вьюер.
viewer.destroy();
```

**Под капотом.** Режим объявлен opt-in до стабилизации (v2): TextLayer
дублирует текст в памяти (runs кадра + DOM-узлы), а DOM ограничен
виртуализацией — spans строятся только для страниц окна ±1. В React смена
объекта опций пересоздаёт вьюер, в Vue/Svelte опция читается только при
монтировании. Кадр при включении не меняется, поэтому цена — только память и
построение DOM, а не качество картинки.

### <a id="a11y-04"></a>Рецепт 4. Известные ограничения

**Задача.** Понимать границы доступного слоя в Спринте 2 и не искать в нём
того, чего нет.

| Ограничение | Влияние | План |
|---|---|---|
| Списки без маркеров и без ролей `list`/`listitem` | копирование теряет маркеры, скринридер читает пункты как абзацы | бэклог: маркеры в сериализаторе и роли списка |
| Колонтитулы, сноски и комментарии не входят в TextLayer | не читаются и не копируются вместе с телом | бэклог: расширение TextLayer |
| URL гиперссылки не несётся в `TextRun` | текст ссылки доступен, адрес — нет | бэклог: поле ссылки в `TextRun` |
| Выделение мышью — только по видимым страницам | drag не покрывает весь документ | Ctrl+A даёт весь текст; точное выделение — Спринт 4 |
| XLSX: только `role="document"` и `aria-hidden` на canvas | DOM-сетки ячеек нет | отдельное решение после Спринта 2 |
| PDF-RTL | RTL-текст в PDF рисуется без bidi | Спринт 3 |
| Точная shaped-ширина арабского не гарантируется | возможен визуальный выход за строку | bbox строки стабилен; shaping — Спринт 3 |
| iOS Safari не проверялся | поведение VoiceOver на iOS неизвестно | Спринт 6 |

```ts
import { createXlsxViewer } from '@meerrec/core';

// То, чего нет в TextLayer, дают экспортные API:
const markdown = await viewer.exportMarkdown(); // списки и URL ссылок
const plain = await viewer.exportText();

// XLSX в Спринте 2 — минимальная обвязка без DOM-сетки:
const xlsx = await createXlsxViewer(host, { a11y: true, workerUrl: xlsxWorkerUrl });
```

**Под капотом.** Копирование — не браузерный `Selection`, а собственный
сериализатор: таблица идёт TSV по логическим `row`/`col`, абзацы разделяются
переводом строки, строки одного абзаца — пробелом. Маркеры списков не
добавляются, потому что canvas их не рисует; полный разбор ограничений и
ручные прогоны — в [чек-листе доступности](../a11y-checklist.md).

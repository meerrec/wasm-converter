# Харнесс спайка x2t (ONLYOFFICE → WASM)

Страница с настоящей конвертацией форматов: файл выбирается в `<input type=file>`, уходит в
модульный воркер, там живёт модуль x2t и MEMFS, назад приезжают байты выхода, код возврата `main`
и stderr. Показываются метрики, предпросмотр (записи zip / текст / hex) и ссылка на скачивание.

Главный элемент страницы — **просмотр документа**: выбранный файл виден страницами на холсте
нашего вьюера (`@doc-converter/core`, `createDocxViewer`), а не списком записей архива.
`.docx` показывается сразу при выборе файла — x2t для этого не нужен; остальные форматы сначала
конвертируются в `docx` тем же воркером x2t, и уже результат открывается в просмотре.

Типизированная обвязка и сами артефакты — в пакете `packages/x2t` (`@doc-converter/x2t`;
`x2t.js` и `x2t.wasm` лежат в `packages/x2t/vendor/`, Git LFS). Харнесс лежит вне
pnpm-workspace и подключает пакет относительным путём `../../packages/x2t/src/index.js`,
а статику берёт из `packages/x2t/vendor` через `publicDir` — копий артефактов в репозитории нет.

## Просмотр документа

Рендерит наш вьюер — тот же, что на странице «Слово» в `examples/viewer`, только подключён
в харнессе:

- ядро — относительным путём `../../packages/core/dist/index.js` (`src/viewer.ts`); сборкой
  ядра страница не занимается, ей нужен собранный `dist`. Имя `@doc-converter/core` здесь
  не резолвится: каталог вне pnpm-workspace;
- воркер вьюера — `src/core_worker.ts` (`import '@doc-converter/core/worker'`) подключён
  суффиксом `?worker&url`: только так Vite собирает его отдельным чанком. Единственный голый
  импорт внутри — `@doc-converter/wasm` — закрыт алиасом в `vite.config.ts`;
- ленивый DOCX-модуль (`packages/wasm-docx/pkg`) отдаётся вьюеру парою URL-ов: JS-обвязка
  и её wasm-бинарь (`src/viewer.ts`). Бинарь передаётся явно — рядом с обвязкой, скопированной
  ассетом, его не оказывается;
- `server.headers` в `vite.config.ts` отдают COOP/COEP: с ними воркер возит кадры через SAB
  (`транспорт sab` в строке просмотра), без них ядро ушло бы на буферы.

Жизненный цикл: вьюер создаётся при первом показе и живёт до перезагрузки страницы —
`DocxViewerHandle.open()` заменяет документ в том же воркере, поэтому холст не плодится
(в разметке он один, сколько бы файлов ни открыли). Отказ разбора документ не открывает, а
вьюер уничтожает (`destroy()`): состояние воркера после падения разбора неизвестно, и следующий
файл получит свежий. На `pagehide` вьюер гасится — воркер держит разобранный документ и wasm.

Модуль x2t поднимается **по первой конвертации** (`ensureBoot` в `src/worker.ts`), а не при
загрузке страницы: 38 МБ не должны быть ценой входа, если страницу открыли ради просмотра
готового `.docx`. Строка «модуль x2t: не поднят» в шапке — это его состояние.

## Запуск

```bash
pnpm -C experiments/x2t-spike install          # свои node_modules: каталог вне workspace
pnpm -C experiments/x2t-spike dev              # страница на порту из vite.config.ts
node experiments/x2t-spike/tools/preview-check.mjs
```

```bash
X2T_SKIP_CONVERT=1 node experiments/x2t-spike/tools/preview-check.mjs   # прогон без x2t: только просмотр
```

`tools/preview-check.mjs` — приёмка через Playwright: поднимает страницу (переиспользует уже
запущенный dev-сервер с того же порта, иначе поднимает свой и гасит за собой) и на фикстуре
`test-fixtures/docx/styles/doc_defaults.docx` проверяет просмотр — холст вьюера ненулевой,
документ разобран на страницы, кадр не пуст (PNG из воркера раскладывается по пикселям, в отчёт
идёт доля непустых и число разных цветов), — а затем, выбрав файл чужого формата, что модуль x2t
от этого не поднимается и целевой формат подставляется сам (`docx`). Дальше идут конвертации:
docx → odt (выход обязан быть zip с записью `mimetype`), docx → txt (непустой выход) и попытка
docx → pdf. Печатает время подъёма модуля (он поднимается внутри первой конвертации), время и
размер каждой конвертации, память (`performance.memory`, если браузер её отдаёт) и исход pdf;
выходы, скриншоты (`viewer-shot.png` — страница, `viewer-host.png` — холст, `viewer-frame.png` —
кадр из воркера) и `preview-check.json` кладёт в `/tmp/x2t-preview-check`. Проверка pdf приёмку
не валит: движка раскладки в сборке нет, и оба известных исхода — «pdf нет». Playwright скрипт
берёт из `examples/viewer` — там стоят браузеры под свою версию, а у копии харнесса их в кэше
может не быть. Переопределения: `X2T_URL`, `X2T_PORT`, `X2T_OUT`, `X2T_TIMEOUT`,
`X2T_VIEWER_TIMEOUT`, `X2T_SKIP_CONVERT`.

**Прогон без x2t**: сторонний wasm в окружении субагента запускать нельзя, поэтому просмотр
(наш вьюер) проверен полным прогоном Playwright — и на dev-сервере, и на сборке, — а конвертации
через x2t и путь «чужой формат → docx → просмотр» остаются за координатором.

## Что известно из прогона в браузере

- Просмотр `.docx` работает: `doc_defaults.docx` — одна страница 794×1123 пкс, холст 958×504,
  транспорт `sab`, кадр 15,4 КиБ, на кадре 83746 непустых пикселей из 482832 и 64 цвета
  (кадр — `/tmp/x2t-preview-check/viewer-frame.png`). То же число на сборке (`vite build` +
  `vite preview`): размер кадра совпал до байта.
- Выбор файла чужого формата (`.xlsx`) модуль x2t не поднимает: состояние модуля остаётся
  «не поднят», целевой формат в `<select>` переключается на `docx`.

## Что известно из прогона в Node (в браузере не перепроверялось)

- docx → odt работает: мелкая фикстура — 19 мс и 3424 Б; реальный документ 5,9 МБ — 1,44 с и 2,8 МБ.
- docx → txt работает, но на реальном документе текст выходит **не в UTF-8** (русский бьётся) —
  похоже, не выставлен `m_nCsvTxtEncoding` в `params.xml`. Открытый вопрос, править — в пакете.

# Хост Euro-Office (self-host из npm-частей)

Статический сайт Euro-Office — это редакторы ONLYOFFICE (форк Euro-Office) целиком
в браузере, с конвертером x2t в WebAssembly. Своего кода здесь нет: сайт не
собирается из исходников, а скачивается шестью готовыми npm-частями
`@kreijstal/eurooffice-*` (версия пинится одной константой `VERSION` в
`assemble.mjs`) и раскладывается overlay'ем в один каталог.

Этот каталог — только **хост редактора**: `assemble.mjs` собирает статику,
`serve.mjs` отдаёт её в дев-режиме. Страница просмотрщика (наша оболочка,
Embed API) живёт отдельно — в примере `examples/viewer`; сюда она не копируется и
публикуется своим маршрутом (`scripts/pages/`). Редактор при этом остаётся
хостом для всех: и дев-страница демо, и публикуемая страница открывают его
iframe'ом (`/editor.html?embed=1`) и работают через Embed API (`postMessage`) в
режиме только просмотра — файл читает родитель и передаёт байтами
(`document:open-buffer`), так что ни CORS, ни сети для этого не нужно.

Всё генерируемое лежит в `build/eurooffice/` (`site/` — собранный сайт, `.cache/`
— тарболы частей и зеркало шрифтов), каталог целиком в `.gitignore`.

**Порядок overlay** (массив `PARTS` в `assemble.mjs`): подчинённые части первыми,

1. `eurooffice-fonts-1`, `eurooffice-fonts-2` — **в npm не опубликованы** (HTTP 404
   на реестре, проверено 14.10.2026), `assemble` говорит об этом и продолжает;
   их роль (движковый каталог `fonts/`) выполняет шаг зеркалирования — см.
   «Каталог шрифтов» ниже;
2. `eurooffice-sdkjs-common` → `sdkjs/common/**` (включая `sdkjs/common/wasm/x2t/`);
3. `eurooffice-web-apps-1` → `web-apps/apps/{common,api,pdfeditor,presentationeditor,visioeditor}`, часть `sdkjs/common/Images`;
4. `eurooffice-web-apps-2` → `web-apps/apps/{common,documenteditor,spreadsheeteditor}`;
5. `eurooffice` → HTML-страницы, `assets/`, `img/`, `ran-fonts/`, `sdkjs/{word,cell,slide,vendor,visio}`, `sw.js` и прочая обвязка сайта.

Пересечение реально проверено: у `web-apps-1` и `web-apps-2` совпадают 190 файлов, и все
они побайтово одинаковы (сплит разрезал дерево, но не менял содержимое); с главным
пакетом пересекаются только `README.md` / `SHA256SUMS` / `LICENSES/*` / `build/*` — их
перекрывает главный, и это единственное место, где порядок что-то решает. Собранный
сайт: **2796 файлов, ~566 МиБ** (`web-apps` 1836, `assets` 90, `sdkjs/common` 396,
`fonts` 203 файла / ~184 МиБ). Кэш — **~292 МиБ** (тарболы частей + зеркало шрифтов);
повторный `assemble` их не перекачивает.

### Каталог шрифтов (`site/fonts/`)

Табличный редактор запрашивает у сайта движковый каталог `/fonts/<индекс>`
(203 файла, суммарно ~184 МБ) по одному файлу за раз, и без него не рисует.
npm-части `eurooffice-fonts-1`/`-2`, которые должны нести каталог, **не
опубликованы**, поэтому `assemble` зеркалирует его из репозитория
[ranuts/document](https://github.com/ranuts/document) (`public/fonts/` — те же
файлы, что на живом сайте): берёт список у GitHub API (без токена, с ретраями),
скачивает `download_url` в `.cache/fonts/` (конкурентность 8, по 2–3 ретрая на
файл; файл из кэша берётся, если он есть и ненулевой) и копирует в `site/fonts/`;
файлы каталога, которых нет в списке, удаляются, чтобы пересборка не копила мусор.

Зависимость от GitHub API — **предупреждение, а не отказ**: при стойкой неудаче
`assemble` печатает «шрифты не скачаны — табличный редактор не будет рисовать» и
выходит с кодом 0. Причина в цене ошибки: сборка сайта — это несколько сотен
мегабайт скачивания, и ронять её из-за чужого rate-limit несоразмерно; поломку
(редактор без шрифтов) ловит браузерная приёмка, а не сборка.

Файлы каталога **XOR-обфусцированы намеренно** (ключ есть в `assets/document-*.js`
и `sdkjs/slide/sdk-all*.js` собранного сайта) — де-XOR выполняет код приложения
в браузере, поэтому файлы зеркалируются как есть, без де-обфускации.

### `x2t.wasm.br`

Части публикуют только несжатый `x2t.wasm` (35,8 МиБ), а редактор ходит за именем
`.br` (`WASM_PATH` в `assets/document-*.js`). Что положить под этим именем —
решает переменная `EUROOFFICE_X2T_BR`:

- **`brotli`** (по умолчанию) — локальная разработка: `assemble` сжимает копию
  zlib'ом из Node с качеством 11 (6,8 МиБ, ~50 с), `serve.mjs` отдаёт её с
  `Content-Encoding: br`. Готовая копия не пересчитывается; пересчитывается, если
  прежняя оказалась несжатой (осталась от режима `copy`).
- **`copy`** — для CI и публикации: под именем `.br` лежат plain-байты `x2t.wasm`
  (перезаписываются безусловно). **GitHub Pages не отдаёт `Content-Encoding: br`**,
  поэтому в публикуемом артефакте под этим именем обязаны лежать несжатые байты —
  иначе браузер попытается разжать wasm как brotli, и редактор не поднимется молча.
  Сжатие в CI к тому же стоило бы 2–4 минуты на каждый прогон.

  Значение переменной проверяется до скачивания частей: опечатка падает сразу, а не
  после пятиминутной распаковки.

`serve.mjs` определяет `.br` **по содержимому**, а не по имени: файл, начинающийся
с сигнатуры `\0asm`, отдаётся как есть (это wasm), иначе — с `Content-Encoding: br`.

## Запуск

```bash
node scripts/eurooffice/assemble.mjs                    # сборка сайта в build/eurooffice/site/ (идемпотентна)
node scripts/eurooffice/serve.mjs                       # http://127.0.0.1:5271/editor
EUROOFFICE_X2T_BR=copy node scripts/eurooffice/assemble.mjs   # как собирает CI: plain-байты под .br
```

Порт `serve.mjs` берётся из аргумента, `VIEWER_PORT` или `PORT` (по умолчанию 5271).
Сервер: MIME-карта (`.wasm` — `application/wasm`, шрифты, картинки), clean URL
(`/editor` → `editor.html`), никаких листингов, `..` не выпускается за корень, 404 —
текстом, умеет `HEAD` (так его проверяет curl). На **все** ответы вешается
`Cross-Origin-Resource-Policy: cross-origin`: в дев-режиме страница демо живёт на
другом origin (`http://localhost:5178`), и её COEP `require-corp` заблокировала бы
кросс-доменный iframe редактора без этого заголовка; в проде всё same-origin, и
заголовок безвреден.

`assemble` проверяет после распаковки, что обязательные пути сайта на месте
(`editor.html`, `assets/editor*.js`, `sdkjs/common/wasm/x2t/x2t.{js,wasm.br}`,
непустые `sdkjs/word/` и `ran-fonts/`, `ran-fonts/fonts.css`) — это проверка
«сборка не развалилась», а не приёмка артефакта.

## Публикация

Собранный сайт уезжает целиком в артефакт публикации: `scripts/pages/stage.mjs`
раскладывает `.pages/` (страница просмотрщика + этот сайт), и там же живут строгие
гейты публикуемого результата. Ключевое, что нужно знать про этот сайт:
`x2t.wasm.br` в `.pages/` намеренно несёт plain-байты (режим `EUROOFFICE_X2T_BR=copy`)
— см. «`x2t.wasm.br`» выше. Приёмка маршрута — `scripts/pages/check-route.mjs` на
staging-сервере; подробности и состав артефакта — в `scripts/pages/` и в workflow
Pages.

## Ограничения

- Пакеты сайта — **AGPL-3.0-only** (у каждой части свои `LICENSES/`); скачиванием и
  раздачей мы ничего не лицензируем заново.
- Просмотр — **только чтение**: страницы открывают редактор с `readonly: true`,
  сохранение выключено. Редактор в сборке полноценный, но обвязка умышленно не даёт
  сохранять.
- PWA/офлайн, совместное редактирование и прочие фичи сайта — не наша забота: сайт
  регистрирует свой service worker и живёт, как живёт; в публикуемом артефакте под
  этим именем лежит наш корневой `sw.js` (см. «Публикация»).
- `serve.mjs` — дев-статик: без сжатия на лету и без Range; для продакшена нужен
  нормальный хостинг статики (у сайта для этого есть `_headers`).

## Файлы

- `assemble.mjs` — скачивание частей в `.cache/`, overlay в `site/`, зеркало шрифтов,
  `x2t.wasm.br` в режиме `EUROOFFICE_X2T_BR`, проверка обязательных путей;
- `serve.mjs` — статик-сервер `site/` (clean URL, MIME, `.br` по содержимому, CORP).
